# White Lamp 账户模块接口说明

本文说明 R02-R04 本地账户模块的调用方式。账户模块只管理身份，不读取或修改游戏进度。

## 运行与脚本顺序

建议在项目根目录使用任意静态服务器。安装了 Python 时可以运行：

```powershell
py -m http.server 8000
```

然后访问 `http://localhost:8000/pages/authorize/login.html`。

没有 Python 时，可使用 VS Code Live Server 或其他本地静态服务器；账户模块不依赖具体服务器软件，也不需要安装前端依赖。

需要在其他页面调用账户接口时，按以下顺序使用 `defer` 加载脚本，路径按页面位置调整：

```html
<script defer src="js/authorize/config.js"></script>
<script defer src="js/authorize/storage.js"></script>
<script defer src="js/authorize/crypto.js"></script>
<script defer src="js/authorize/auth-service.js"></script>
```

开发阶段登录成功地址由 `js/authorize/config.js` 中的 `successUrl` 统一指向 `test/authorize/demo.html`。主菜单完成后，只修改该地址，不修改认证服务。

## 公开接口

接口位于 `window.WhiteLamp.auth`，所有方法都返回 `Promise<AuthResult>`：

```js
const sessionResult = await window.WhiteLamp.auth.getSession();

if (!sessionResult.ok) {
  // 必须向用户显示 sessionResult.message，不能假装成未登录。
  console.error(sessionResult.code, sessionResult.message);
} else if (sessionResult.data === null) {
  // 当前没有会话，应跳转登录页或显示登录入口。
} else {
  const { userId, username, userType, storageScope } = sessionResult.data;
  console.log(userId, username, userType, storageScope);
}
```

公开方法：

| 方法 | 输入 | 成功时的 `data` | 用途 |
| --- | --- | --- | --- |
| `register(input)` | `username`、`password`、`confirmPassword`、`acceptedStorage` | `{ username }` | 创建本地账户，不自动登录 |
| `login(input)` | `username`、`password` | `PublicUser` | 验证账户并创建当前会话 |
| `enterGuest()` | 无 | `PublicUser` | 创建固定游客会话 |
| `getSession()` | 无 | `PublicUser` 或 `null` | 获取当前公开身份 |
| `logout()` | 无 | 无 | 仅清除会话 |

`PublicUser` 的固定结构：

```js
{
  userId: "账户 UUID 或 guest",
  username: "注册用户名或游客",
  userType: "account 或 guest",
  storageScope: "account:<userId> 或 guest"
}
```

其他模块不得读取 `white-lamp:auth:accounts:v1`。游戏存档模块只需把 `storageScope` 纳入自己的存档键，例如：

```js
const saveKey = `white-lamp:save:${sessionResult.data.storageScope}:v1`;
```

## 结果与错误处理

成功结果的 `ok` 为 `true`；失败结果的 `ok` 为 `false`，并包含用户可见的 `message` 和稳定的 `code`。表单校验失败时还会返回 `fieldErrors`。

| 错误码 | 含义 |
| --- | --- |
| `VALIDATION_FAILED` | 输入不符合规则或缺少必填项 |
| `USERNAME_TAKEN` | 用户名已被当前浏览器中的账户使用 |
| `INVALID_CREDENTIALS` | 用户名或密码不正确 |
| `STORAGE_UNAVAILABLE` | 浏览器拒绝或无法使用本地存储 |
| `STORAGE_CORRUPTED` | 账户数据无法解析、结构错误或版本不符 |
| `SESSION_CORRUPTED` | 当前会话无法解析或引用了不存在的账户 |
| `CRYPTO_UNAVAILABLE` | Web Crypto 不可用或摘要计算失败 |
| `UNEXPECTED_ERROR` | 模块依赖缺失等未预期错误 |

存储损坏时模块不会自动删除或覆盖原数据。界面应显示返回的错误信息；技术细节会以 `[white-lamp:authorize]` 前缀写入控制台。

## 会话与退出

- 账户集合保存在 `localStorage`，关闭浏览器后仍保留。
- 当前身份保存在 `sessionStorage`，刷新页面仍保留，关闭浏览器后需要重新登录。
- 游客的 `storageScope` 固定为 `guest`，不会覆盖注册账户的数据域。
- `logout()` 只清除当前会话，不删除本地账户，也不删除任何游戏存档。

## 自动化测试

在项目根目录运行：

```powershell
node test/authorize/auth-service.test.js
```

测试使用内存存储，不会读写真实浏览器中的账户数据。它覆盖输入校验、密码摘要、大小写查重、登录与退出、公开字段、多个账户和游客隔离、损坏数据以及浏览器能力不可用等路径。
