账户模块只管理用户身份。游戏进度仍由存档模块负责，两个模块通过 `storageScope` 关联。

主菜单自己的入口脚本放在这些脚本之后。下面只展示接入顺序，其中 `showError()`、`showCurrentUser()` 和 `loadSaveFor()` 需要由主菜单与存档模块实现，不能把这段当成完整脚本直接复制：

```js
const sessionResult = await window.WhiteLamp.auth.getSession();

if (!sessionResult.ok) {
  // 必须在页面显示 message，同时保留控制台错误，不能当作未登录跳过。
  showError(sessionResult.message);
} else if (sessionResult.data === null) {
  window.location.replace("authorize/login.html");
} else {
  const { username, userType, storageScope } = sessionResult.data;
  showCurrentUser(username, userType);
  loadSaveFor(storageScope);
}
```

退出按钮调用 `await window.WhiteLamp.auth.logout()`。只有结果的 `ok` 为 `true` 时，才跳回 `authorize/login.html`。

## 运行方式

账户和密码摘要依赖浏览器存储及 Web Crypto，正式测试应通过本地静态服务器访问，不能只双击 HTML 文件。

安装了 Python 时，在项目根目录运行：

```powershell
py -m http.server 8000
```

然后访问：

```text
http://localhost:8000/pages/authorize/login.html
```

没有 Python 时可使用 VS Code Live Server。账户模块不依赖具体的服务器软件，也不需要安装前端依赖。

## 公开接口

接口位于 `window.WhiteLamp.auth`。所有方法都返回 `Promise<AuthResult>`，调用方必须先判断 `ok`。

| 方法 | 输入 | 成功时的 `data` | 用途 |
| --- | --- | --- | --- |
| `register(input)` | `username`、`password`、`confirmPassword`、`acceptedStorage` | `{ username }` | 创建本地账户，不自动登录 |
| `login(input)` | `username`、`password` | `PublicUser` | 验证账户并建立会话 |
| `enterGuest()` | 无 | `PublicUser` | 建立固定游客会话 |
| `getSession()` | 无 | `PublicUser` 或 `null` | 读取当前身份 |
| `logout()` | 无 | 无 | 只清除当前会话 |

`PublicUser` 固定包含四个字段：

```js
{
  userId: "账户 UUID 或 guest",
  username: "注册用户名或游客",
  userType: "account 或 guest",
  storageScope: "account:<userId> 或 guest"
}
```

其他模块不得读取账户列表或密码摘要。游戏存档模块只使用 `storageScope` 区分数据，例如：

```js
const saveKey = `white-lamp:save:${sessionResult.data.storageScope}:v1`;
```

## 存储与错误

- 账户集合保存在 `localStorage["white-lamp:auth:accounts:v1"]`。
- 当前会话保存在 `sessionStorage["white-lamp:auth:session:v1"]`。
- 刷新页面会保留会话；正常关闭标签页或浏览器后需要重新登录。
- 游客固定使用 `guest` 存储域，不会覆盖注册账户的数据。
- `logout()` 不删除账户，也不删除游戏存档。
- 损坏数据不会被自动覆盖或删除。

失败结果会提供用户可读的 `message` 和错误码。表单校验失败时还会提供 `fieldErrors`。

| 错误码 | 含义 |
| --- | --- |
| `VALIDATION_FAILED` | 输入为空或不符合规则 |
| `USERNAME_TAKEN` | 用户名已存在，比较时忽略大小写 |
| `INVALID_CREDENTIALS` | 用户名或密码错误 |
| `STORAGE_UNAVAILABLE` | 浏览器存储不可用 |
| `STORAGE_CORRUPTED` | 账户数据损坏或版本不符 |
| `SESSION_CORRUPTED` | 当前会话损坏或引用了不存在的账户 |
| `CRYPTO_UNAVAILABLE` | Web Crypto 不可用 |
| `UNEXPECTED_ERROR` | 依赖缺失等未预期错误 |

页面必须展示失败结果中的 `message`。技术细节会以 `[white-lamp:authorize]` 前缀写入控制台，不能只在控制台报错后继续假装成功。

## 真实浏览器测试清单

以下测试使用专门的测试用户名，不要在已有游戏数据的浏览器环境里随意清空整个站点。

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| B01 注册校验 | 注册时输入用户名 `a!`、密码 `123`、不同的确认密码，并且不勾选本地存储同意项 | 四个字段分别显示原因，页面不跳转，控制台没有未处理异常 |
| B02 正常注册 | 使用 `Player01` 和 `DemoPass123` 注册并勾选同意项 | 返回登录页，显示注册成功，用户名已预填，但没有自动登录 |
| B03 重名与登录 | 再注册 `player01`，随后分别尝试错误密码和正确密码 | 大小写不同仍提示用户名已存在；错误密码只提示“用户名或演示密码不正确”；正确密码进入当前配置的成功页面 |
| B04 会话与退出 | 登录后刷新成功页面，再点击退出，然后重新登录 | 刷新后身份不丢失；退出后回到登录页；原账户仍能再次登录 |
| B05 游客与隔离 | 退出账户后选择游客进入；记录游客的 `storageScope`，再登录 `Player01` 比较 | 进入前出现游客提示；游客域为 `guest`；注册账户域为 `account:<UUID>`，两者不同 |
| B06 密码未明文保存 | 在开发者工具 Application 中查看 `white-lamp:auth:accounts:v1` | 能看到用户名、盐和摘要，但搜索不到明文 `DemoPass123` |
| B07 损坏数据可见 | 先备份账户存储值，再在控制台写入无效 JSON：`localStorage.setItem("white-lamp:auth:accounts:v1", "{broken")`，然后登录 | 页面明确提示本地账户数据损坏；原来的 `{broken` 没有被覆盖；游客入口仍可用。测试后恢复备份值 |
| B08 响应式与键盘 | 分别在 Chrome、Edge 和 390px 设备模式打开登录、注册页；只用 Tab、Space、Enter 完成一次操作 | 没有横向滚动、文字遮挡或按钮跳位；焦点清楚；密码显示按钮、复选框和主要操作都可用；控制台无资源 404 和未处理异常 |

执行 B07 前，在开发者工具 Console 中备份账户数据：

```js
const accountKey = "white-lamp:auth:accounts:v1";
const backupKey = "white-lamp:auth:accounts:v1:test-backup";
const currentAccounts = localStorage.getItem(accountKey);

if (currentAccounts === null) {
  localStorage.removeItem(backupKey);
} else {
  localStorage.setItem(backupKey, currentAccounts);
}
```

测试完成后恢复，并删除临时备份：

```js
const accountBackup = localStorage.getItem(backupKey);

if (accountBackup === null) {
  localStorage.removeItem(accountKey);
} else {
  localStorage.setItem(accountKey, accountBackup);
}

localStorage.removeItem(backupKey);
```

完成 B01-B08 后，再将成功地址切到主菜单，重复 B03-B05。只有账户登录、已有会话和游客三条路径都能进入主菜单，才能删除 Demo。
