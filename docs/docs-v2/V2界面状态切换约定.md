# 《借灯》V2 界面状态与页面容器交接约定

> **状态：2026-09-08 合并终稿。** 本文已经合并原《V2界面状态切换约定》和《V2-game-ui-container-spec》的有效内容，是 V2 正式 `pages/game.html` 的页面状态、容器和显隐规则唯一交接文档。

## 1. 本文解决什么问题

本文只回答四件事：

1. 当前页面处于哪一种状态；
2. 哪些容器显示，哪些内容可以点击；
3. 打开、关闭、成功、取消或失败后去哪里；
4. 谁负责决定游戏流程，谁负责切换页面。

本文不决定剧情 Node，不编写剧情、热点、对话、拼图规则或场景美术。

## 2. 文件职责边界

| 文件或模块 | 负责什么 | 不负责什么 |
|---|---|---|
| `navigation.js` | 登录检查、主菜单按钮、退出登录、返回菜单和 URL 跳转 | 不创建游戏流程，不挂载探索或小游戏，不切换游戏内容容器 |
| `game-page-controller.js` | 启动正式游戏页；组装 `game-flow`、阅读、探索、小游戏和成就；连接 DOM；控制页面状态、覆盖层、保存按钮和清理 | 不决定剧情 Node，不生产探索事实，不实现具体玩法 |
| `game-flow.js` | 接收事件、调用剧情、提交状态、发布最新 `status/presentation/commands` | 不直接操作页面容器，不实现探索或拼图界面 |
| `state.js` | 校验并提交事实和游戏状态 | 不操作 DOM，不决定页面显示 |
| `storage.js` | 读写并验证游戏存档 | 不决定剧情和页面状态 |
| `exploration` / `conversation` / `minigame` | 实现各自玩法并报告玩家实际完成的结果 | 不自行修改 `storyCheckpoint`，不决定下一个 Node，不直接切换其他模块容器 |

正式调用关系：

```text
玩家操作
  → 业务模块报告结果
  → game-flow 提交状态并调用剧情
  → game-flow 发布最新响应和完整命令
  → game-page-controller 切换页面并更新模块
```

## 3. 已确认的页面安排

### 3.1 页面结构

```text
┌───────────────────────────────────────────────────────────┐
│ 返回菜单  章节名                    背包  地图  成就  保存 │
├───────────────────────────────────────────────────────────┤
│ #feedback：玩家提示                                      │
├───────────────────────────────────────────────────────────┤
│                                                           │
│ #game-scene                                               │
│   └─ #exploration-actions                                 │
│                                                           │
│ reading 时：                                               │
│   #game-story + #game-actions                              │
│   作为场景底部对话框覆盖显示                               │
│                                                           │
│ #inventory-panel   默认隐藏，打开时成为覆盖层              │
│ #detail-root       默认隐藏，打开时成为覆盖层              │
│ #minigame-root     默认隐藏，打开时成为覆盖层              │
```

### 3.2 正式容器清单

| 容器 | 性质 | 显示规则 | 内容负责人 |
|---|---|---|---|
| `#feedback` | 固定反馈区 | 有提示时显示，否则 `hidden` | `game-page-controller.js` 连接，各模块提供提示含义 |
| `#return-menu-button` | 顶栏导航按钮 | 始终显示 | `navigation.js` 提供跳转，控制器连接按钮 |
| `#save-button` | 顶栏保存按钮 | 始终显示 | `game-page-controller.js` |
| `#open-inventory-button` | 顶栏背包入口 | reading / exploration 时可用 | `game-page-controller.js` |
| `#open-minigame-button` | 顶栏地图入口 | 有合法地图命令且处于 reading / exploration 时可用 | `game-page-controller.js` |
| 成就入口 | 顶栏导航链接 | 始终显示，跳转现有成就页 | 页面/UI |
| `#chapter-name` | 顶栏章节名 | 始终显示，只显示玩家可读章节名 | `game-page-controller.js` 根据已提交状态填充 |
| `#game-scene` | 场景基础层和阅读背景 | exploration 时可操作；reading 时保留为锁定背景 | 探索模块 |
| `#exploration-actions` | 场景热点和人物入口 | exploration 时显示且可点；作为背景时锁定 | 探索模块 |
| `#game-story` | 阅读内容/对话正文 | reading 时显示在场景底部对话框内 | 统一阅读组件 |
| `#game-actions` | 阅读按钮 | reading 时显示在场景底部对话框内且可点 | 统一阅读组件 |
| `#inventory-panel` | 背包覆盖层 | inventory 时显示，其余时间 `hidden` | 探索/背包模块 |
| `#detail-root` | 详情覆盖层 | detail 时显示，其余时间 `hidden` | 探索/详情模块 |
| `#minigame-root` | 小游戏覆盖层 | minigame 时显示，其余时间 `hidden` | 拼图 adapter |

已确认的 DOM 调整：

- `#inventory-panel` 从永久 `<aside>` 侧栏改为默认 `hidden` 的覆盖层；
- 新增 `#detail-root`；
- 顶栏新增背包、地图、成就入口和 `#chapter-name`；
- 场景层不拆分，继续使用 `#game-scene` 和 `#exploration-actions`；
- 阅读层继续使用 `#game-story` 和 `#game-actions`，不新增独立阅读 ID。

### 3.3 橙光式阅读布局

- 场景背景保持 `16:9`；`reading` 状态继续显示场景，但场景和热点都由状态协调器锁定，不能穿透点击。
- `.story-panel` 覆盖在场景下缘；`#game-story` 是正文区，`#game-actions` 是右下操作区，二者组成同一个半透明深色对话框。
- 桌面端对话框与场景左右保留安全边距，最大高度不超过场景的 `44%`；窄屏可提高到 `68%`，但仍留出可辨认的场景区域。
- 一次只显示一个 `block` 或 `dialogue`。正文区不出现滚动条；玩家点击“继续”，最后一段点击“读完”，然后才显示剧情 action 或触发 NPC 阅读完成回调。
- NPC 正文若以 `【角色】`、`【旁白】` 或 `【系统提示】` 开头，阅读组件把这个**已有标签**移到对话框姓名牌，并从正文开头移除；没有合法开头标签时不猜说话人，也不把顶层 `speaker` 套到每一段。
- 姓名牌只是原文标签的视觉重排，不新增 `speakerRole` 等输入字段；`lineId`、`commandId`、Node ID 和事实 ID 一律不显示。
- 对话框使用固定高度、安全内边距、金色细边框和深色半透明底；按钮保持可见焦点和至少约 `40px` 的点击高度。
- 对话框不得遮挡已确认的关键场景对象和热点安全区；杨梦交付正式构图后，用 390/768/1280px 三个视口共同复核。
- `exploration` 状态隐藏整个 `.story-panel` 并恢复热点操作；背包、详情或拼图覆盖在阅读层上方时，阅读层保留但锁定。

该规则只规定页面呈现方式，不改变 `presentation`、`dialogues[]`、`commands`、事实或剧情推进接口。

### 3.4 页面层级

```text
顶栏和 #feedback                              z-index: 100
#detail-root/#inventory-panel/#minigame-root  z-index: 50
reading 或 exploration 基础内容              z-index: 0
```

隐藏区域必须不占位、不接收点击。

## 4. 五种页面状态

| 状态 | 用人话解释 |
|---|---|
| `reading` | 玩家正在阅读旁白、系统文字或人物对话 |
| `exploration` | 玩家正在场景中点击物体或选择人物 |
| `detail` | 玩家正在查看线索详情 |
| `inventory` | 玩家正在查看背包和已获得线索 |
| `minigame` | 玩家正在玩地图拼图 |

同一时刻只能有一个**当前可操作状态**。

`detail`、`inventory`、`minigame` 是覆盖层。覆盖层打开时，上一个界面可以留在下面显示，但它只是锁定背景，不是第二个可操作状态。

## 5. 状态显隐和点击规则

| 当前可操作状态 | 返回目标 | 场景和热点 | 阅读内容和按钮 | 背包 | 详情 | 拼图 |
|---|---|---|---|---|---|---|
| `reading` | 无 | 显示、锁定 | 显示、可点 | 隐藏 | 隐藏 | 隐藏 |
| `exploration` | 无 | 显示、可点 | 隐藏 | 隐藏 | 隐藏 | 隐藏 |
| `detail` | `reading` | 隐藏 | 显示、锁定 | 隐藏 | 显示、可点 | 隐藏 |
| `detail` | `exploration` | 显示、锁定 | 隐藏 | 隐藏 | 显示、可点 | 隐藏 |
| `detail` | `inventory` | 保留 inventory 原来的锁定背景 | 按原返回链处理 | 显示、锁定 | 显示、可点 | 隐藏 |
| `inventory` | `reading` | 隐藏 | 显示、锁定 | 显示、可点 | 隐藏 | 隐藏 |
| `inventory` | `exploration` | 显示、锁定 | 隐藏 | 显示、可点 | 隐藏 | 隐藏 |
| `minigame` | `reading` | 隐藏 | 显示、锁定 | 隐藏 | 隐藏 | 显示、可点 |
| `minigame` | `exploration` | 显示、锁定 | 隐藏 | 隐藏 | 隐藏 | 显示、可点 |

顶栏规则：

- 返回菜单、保存和成就入口保持可用；
- 背包和地图入口只在 `reading` 或 `exploration` 状态接受打开请求；
- 已经打开覆盖层时，不再从顶栏叠加另一个业务覆盖层；
- 从 inventory 点击线索打开 detail 属于明确的业务跳转，允许 detail 覆盖 inventory。

## 6. 剧情响应到页面状态的映射

页面不能根据按钮文字猜剧情进度，必须读取 `game-flow` 发布的最新 `status`、`presentation` 和完整 `commands`。

| 最新剧情响应 | 页面处理 |
|---|---|
| `ready` + `presentation` | 进入 `reading`，显示剧情或对白 |
| `waiting-external` + `REQUEST_EXPLORATION` | 进入或保持 `exploration`，等待玩家调查物体 |
| `waiting-external` + `REQUEST_CONVERSATION` | 进入或保持 `exploration`，等待玩家选择人物；选择后才进入阅读 |
| `waiting-external` + `REQUEST_MINIGAME` | 保持 `exploration` 或当前允许的基础状态，并显示地图入口；玩家主动打开后才进入 `minigame` |
| 同时存在多个村民命令 | 保持 `exploration`，由玩家选择一个；不能自动执行第一个，也不能同时打开多个对话 |
| `ended` | 进入 `reading`，使用 `#game-story` 和 `#game-actions` 显示结束内容；`commands` 必须为空 |
| `error` | 保留最近一个有效页面状态，显示玩家能理解的错误提示；不清空状态、不推进剧情 |

如果未来同时出现不同类型、且无法按上表唯一决定页面的命令，`game-page-controller.js` 应报告接口冲突，不自行猜优先级。

## 7. 五种状态的进入和返回

| 状态 | 进入条件 | 正常完成 | 取消或关闭 | 失败 |
|---|---|---|---|---|
| `reading` | 收到 `ready + presentation`；或玩家选择人物后打开对话 | 最后一段只回调一次；由最新剧情响应决定下一状态 | 返回打开阅读前的合法状态；不提交事实、不推进 Node | 保留当前内容和检查点，显示可理解提示 |
| `exploration` | 收到调查/对话命令 | 把真实事件交给 `game-flow`；只有提交成功后才显示已完成，并按最新响应更新页面 | 保持 exploration，不提交事实 | 保持 exploration；热点不得伪装成完成 |
| `detail` | 从 reading、exploration 或 inventory 打开已获得线索 | 关闭并回 `returnState`；重复查看不产生事实或奖励 | 回 `returnState` | 保留原数据，显示详情读取失败提示 |
| `inventory` | 从 reading 或 exploration 点击背包 | 关闭并回 `returnState`；只读显示已提交内容 | 回 `returnState` | 保留已有内容，不伪造初始列表 |
| `minigame` | 有合法 `REQUEST_MINIGAME`，玩家从 reading 或 exploration 主动打开 | 提交 `MAP_PUZZLE_COMPLETED`；成功后由 `game-flow` 的最新响应决定下一状态 | 回 `returnState`，不产生完成事实 | 可留在拼图重试，或取消后回 `returnState`；不得提交完成事实 |

## 8. 覆盖层统一规则

### 8.1 打开

业务模块只提出请求：

```text
请求类型：detail | inventory | minigame
目标 ID：线索 ID、地图命令 ID 等
```

`game-page-controller.js` 必须自己完成：

1. 读取当前状态；
2. 把当前状态记录为 `returnState`；
3. 记录打开前的焦点；
4. 显示目标覆盖层；
5. 锁定下面所有内容按钮。

调用方不能填写或伪造 `returnState`，业务模块不能直接修改其他容器的 `hidden` 属性。

如果从 inventory 再打开 detail，每一层都保留自己的返回目标。关闭 detail 先回 inventory；关闭 inventory 再回更早的 reading 或 exploration。

### 8.2 关闭或取消

- 清理当前覆盖层的临时监听；
- 回到 `returnState`；
- 恢复打开前的焦点；
- 不提交事实；
- 不改变 `storyCheckpoint`。

### 8.3 成功或失败

- 成功：真实玩法事件交给 `game-flow.handleExternalEvent`；只有返回 `ok: true` 后才刷新完成状态。
- 拼图成功：不直接回 `returnState`，由 `game-flow` 的最新剧情响应决定下一界面。
- 失败：保留当前有效状态和已有数据，显示玩家能理解的提示。

## 9. 存档恢复规则

恢复时不能根据旧 DOM、旧动画位置或拼图中途布局猜页面。

统一顺序：

1. `storage.js` 读取并验证存档；
2. `game-flow.js` 根据已保存的 `storyCheckpoint` 恢复剧情；
3. 先发布完整 `commands`，再通知页面和模块；
4. `game-page-controller.js` 根据最新响应重建唯一的当前可操作状态。

恢复映射：

```text
ready + presentation                       → reading
waiting-external + 调查/对话命令           → exploration
waiting-external + 地图命令                → exploration 并显示地图入口
ended                                      → reading 结束展示
无档/坏档/版本不兼容/存储不可用            → 显示对应提示，不伪装成新游戏
```

恢复必须保留：

- 最新 `storyCheckpoint`；
- 已提交的 `facts`；
- 完整 `commands`，包括执行需要的 `commandId`、`commandType`、`payload` 和 `goals`；
- 原存档数据和可返回路径。

拼图只保存是否完成，不保存中途布局。未完成拼图恢复后回到基础状态并重新显示合法地图入口，不自动打开旧拼图画面。

## 10. 玩家反馈和内部信息

正式页面只显示玩家能理解的中文剧情、调查结果和下一步提示。

下列内容只能进入开发者控制台：

```text
Node
eventType
commandId
事实 ID
错误码
函数名
调用栈
内部状态对象
```

必须区分以下反馈：

- 没有存档；
- 存档损坏；
- 存档版本不兼容；
- 浏览器存储不可用；
- 操作失败；
- 保存成功。

各模块负责提供提示含义；`game-page-controller.js` 负责统一送到 `#feedback`，并阻止内部字段直接显示给玩家。

## 11. 响应式和点击验收

必须分别在浏览器内容区域宽度为 390、768、1280px 时检查：

- 页面没有横向溢出；
- 文字、按钮和关键场景物体没有被遮住；
- 场景图片按固定比例缩放；
- 热点与场景图使用同一个坐标容器并一起缩放；
- 热点和按钮有足够的鼠标点击区域；
- 图片加载失败时仍有文字提示和返回操作。

问题归属：

| 问题 | 负责人 |
|---|---|
| 图片内容、裁切和对比度 | 杨梦 |
| 容器布局、缩放和覆盖层 CSS | 高冰轩 |
| 热点坐标和点击结果 | 卢正松 |

| 剧情顺序和剧情响应内容 | 于知让 |

## 12. 阅读组件交接边界

统一阅读组件挂载到：

```text
#game-story
#game-actions
```

它至少提供：

```text
open(input)       打开并显示阅读内容
close()           强制关闭，不提交事实
onComplete        最后一段结束时只触发一次
onAction          玩家选择合法剧情操作时触发
```

规则：

- 一次只显示一个文本块；
- “继续阅读”只移动阅读位置，不自动当作剧情 action；
- 缺少必要字段时报告字段名，不自行补写剧情；
- NPC 对话的数据结构由对话模块提供，不能假装成普通剧情块；
- 对话完成前不能提前提交 `NPC_TALKED`。

## 14. 最小验收路径

在正式 `pages/game.html` 至少验证：

1. `ready → reading`：逐段阅读，连续点击不重复提交；
2. `waiting-external → exploration`：一个物体成功、失败、连续点击各一次；
3. 探索中打开详情，背景点不动，关闭后原热点仍可点击；
4. 阅读和探索分别打开背包，关闭后回到各自的打开前状态；
5. 两个村民命令同时出现时保持探索，由玩家选择一个；
6. 阅读和探索分别打开地图，取消后回各自 `returnState`；
7. 拼图完成后提交事实，并由最新剧情响应决定下一界面；
8. 阅读中、调查后、地图完成后分别保存，继续游戏后重建正确界面；
9. 无档、坏档、版本不兼容和存储不可用显示不同提示，均不伪装成新游戏；
10. 在 390、768、1280px 下检查溢出、遮挡、热点位置和背景穿透点击。

```text
预期事件/事实：应该产生什么结果
预期存档：storyCheckpoint/facts 是否变化
实际结果：页面、控制台和存档发生了什么
归属：页面 / 剧情 / 探索 / 美术 / 全局存档
复测：修复后由原报告人沿同一路径重新确认
```
