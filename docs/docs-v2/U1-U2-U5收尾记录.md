# U1、U2、U5 收尾记录

> 基线：PR #33，提交 `071afbc`。
> 范围：严格限定在《项目需求文档 v2》“高冰轩｜游戏页面与统一阅读组件”的文件和职责边界内。

## 边界确认

本次没有修改 `navigation.js`、剧情推进、事实提交、探索事件规则、热点坐标、场景展示字段或小游戏业务逻辑。PR #33 提供的 `sceneId`、`sceneVariant`、`sceneImage`、`itemId` 和 `detailImage` 由探索展示侧产生，页面继续只消费稳定展示结果，不从 facts 推导场景状态。

## U1 游戏页结构重构

技术实现关闭：

- 正式页所需导航、反馈、场景、探索操作、阅读、背包、详情和小游戏挂载点均存在且 ID 唯一。
- 背包、详情、小游戏默认 `hidden`；隐藏规则不占位，锁定层不接收指针操作。
- 地图 adapter 只挂载到 `#minigame-root`，容器内不预置另一套游戏页面。
- 以上结构由 `test/core/game-page-shell-contract.test.mjs` 持续检查。

## U2 统一阅读组件

技术实现关闭：

- 剧情和 NPC 对话统一使用 `open/update/next/close`；一次只显示一个 item。
- 普通 action 只在末尾出现，完成回调同一会话只触发一次，关闭不会触发完成。
- NPC Choice 接受一个提示和 2 至 4 个业务方已冻结选项，不在 UI 内推断分支。
- 输入会明确检查 `mode/items/actions/metadata`、条目字段、类型匹配和 ID 唯一性；对话适配器会明确报告缺少 `conversation.dialogues`。
- 异步提交时按钮禁用并显示忙碌提示；失败时仅显示玩家可读的重试提示并恢复按钮。
- 组件只发出回调，不调用 game-flow，不写 facts、剧情检查点或存档。

## U5 玩家可读的页面反馈

高冰轩侧技术实现关闭：

- 正式页面保留唯一 `#feedback`，具有 `role="status"`、`aria-live="polite"`，无提示时默认隐藏。
- 页面不预置流程日志、命令详情或联调按钮；阅读正文和操作文案通过 `textContent` 写入。
- 六类正式反馈均包含玩家可读说明和下一步动作：无存档、坏档、版本不兼容、存储不可用、操作失败、保存成功。
- 阅读操作的异常对象只写控制台，页面仅显示固定重试文案。
