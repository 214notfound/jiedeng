# 《借灯》全局板块接口说明

> 面向：剧情、探索、背包、拼图、成就、账户、页面与视觉模块成员。  
> 当前版本：V1.0（`state.js` 已完成；`storage.js`、`navigation.js` 待接入。）

## 先看这一页：你需要做什么

如果你的模块让游戏发生了“需要在刷新或读档后记住”的事情，不要直接改背包、成就、剧情节点或浏览器存储。请向全局状态模块发送一个标准事件，并接住它返回的新状态：

```js
gameState = applyGameEvent(gameState, event);
```

下面这些事情必须通过事件更新：

- 获得物品、调查对象、首次与人物对话；
- 作出会影响后续内容的选择；
- 改变剧情节点或阶段；
- 完成地图拼图；
- 解锁成就。

打开或关闭背包、临时提示文字、鼠标位置等不需要存进游戏状态。

## 1. 模块边界

| 模块 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 账户 | 注册、登录、游客会话，提供当前用户的 `storageScope` | 游戏进度、背包、剧情状态 |
| 全局状态 `state.js` | 创建初始状态、根据事件生成新状态、自动去重 | 读写 `localStorage`、页面视觉、账号密码 |
| 存档 `storage.js` | 保存、读取、校验游戏状态 | 修改剧情、物品或成就 |
| 业务模块 | 展示内容、响应用户点击、发出事件 | 直接改状态对象、直接保存游戏 |

禁止以下写法：

```js
gameState.inventory.push("key-a");
gameState.achievements.push("map-restorer");
localStorage.setItem("white-lamp:save:guest:v1", "...");
```

## 2. 与账户模块如何对接

账户模块公开接口是 `window.WhiteLamp.auth`，游戏模块只需要关心它返回的 `storageScope`。

```js
const sessionResult = await window.WhiteLamp.auth.getSession();

if (!sessionResult.ok) {
  // 在页面显示 sessionResult.message，不要继续创建或读取游戏状态。
} else if (sessionResult.data === null) {
  // 没有会话，跳回登录页。
  window.location.replace("authorize/login.html");
} else {
  const { storageScope } = sessionResult.data;
  // 新游戏：createInitialGameState(storageScope)
  // 继续游戏：由后续 storage.js 读取此 storageScope 对应的存档。
}
```

`storageScope` 的唯一合法格式：

| 玩家身份 | `storageScope` | 说明 |
| --- | --- | --- |
| 游客 | `guest` | 所有游客使用同一个游客进度域 |
| 注册账户 | `account:<userId>` | `userId` 是账户模块生成的 UUID |

不要使用 `username` 当存档键；不要读取账户列表、密码摘要或 `sessionStorage`。

主菜单需要按下面顺序加载账户脚本；自己的全局入口脚本放在其后：

```html
<script defer src="../assets/js/authorize/config.js"></script>
<script defer src="../assets/js/authorize/storage.js"></script>
<script defer src="../assets/js/authorize/crypto.js"></script>
<script defer src="../assets/js/authorize/auth-service.js"></script>
<script type="module" src="../assets/js/core/navigation.js"></script>
```

## 3. 当前 `state.js` 的公开接口

文件：`assets/js/core/state.js`

```js
import {
  GAME_EVENTS,
  createInitialGameState,
  applyGameEvent
} from "../core/state.js";
```

### 3.1 创建新游戏

```js
let gameState = createInitialGameState(storageScope);
```

新游戏固定从 `prologue-wake`、`prologue` 开始。传入非法的 `storageScope` 会抛出错误，避免账户存档与游客存档串在一起。

### 3.2 更新状态

```js
gameState = applyGameEvent(gameState, {
  type: GAME_EVENTS.ITEM_ACQUIRED,
  payload: {
    itemId: "key-a"
  }
});
```

`applyGameEvent()` 不会修改传入的旧对象，而是返回新对象。因此必须写回 `gameState`。错误事件或错误 ID 会抛出错误；页面模块应捕获错误、写入控制台，并给玩家可理解的提示。

```js
try {
  gameState = applyGameEvent(gameState, event);
} catch (error) {
  console.error("[white-lamp:global] 状态更新失败", error);
  // 例如：showFeedback("操作未完成，请重试。", "error");
}
```

### 3.3 游戏状态结构

```js
{
  schemaVersion: 1,
  storageScope: "guest 或 account:<userId>",
  currentNodeId: "prologue-wake",
  stage: "prologue",
  stageProgress: { "prologue-started": true },
  choices: {},
  investigated: [],
  talkedTo: [],
  inventory: [],
  puzzle: { mapRestored: false },
  achievements: [],
  updatedAt: null
}
```

业务模块可以读取这些字段，但不得删除字段、改字段名或直接修改数组。`updatedAt` 由后续存档模块在保存成功时写入。

## 4. 事件速查表

所有 `payload` 中的内容 ID 都必须是小写 kebab-case，例如 `key-a`、`prologue-wake`、`map-puzzle`。

| 事件 | 何时发出 | `payload` | `state.js` 自动完成 |
| --- | --- | --- | --- |
| `GAME_STARTED` | 游戏内确认重新开始 | 无 | 重建初始状态，保留当前 `storageScope` |
| `STORY_NODE_CHANGED` | 剧情进入另一个节点 | `{ nodeId, stageId }` | 更新当前节点和阶段 |
| `STAGE_PROGRESS_UPDATED` | 阶段任务完成或取消 | `{ progressId, completed }` | 更新任务标记；`completed` 必须是 `true` 或 `false` |
| `OBJECT_INVESTIGATED` | 调查物品/热点 | `{ objectId, itemId? }` | 记录对象；可选地加入物品 |
| `NPC_TALKED` | 首次完成角色对话 | `{ npcId, rewardItemId? }` | 记录角色；可选地加入奖励 |
| `CHOICE_MADE` | 作出需保留的剧情选择 | `{ choiceId }` | 写入 `choices[choiceId] = true` |
| `ITEM_ACQUIRED` | 获得独立物品 | `{ itemId }` | 把物品加入背包 |
| `MAP_PUZZLE_COMPLETED` | 手绘地图复原成功 | `{ puzzleId: "map-puzzle" }` | 地图已复原、加入完整地图、解锁成就、开放老宅 |
| `ACHIEVEMENT_UNLOCKED` | 解锁其他成就 | `{ achievementId }` | 把成就加入成就列表 |

背包、调查、对话和成就都会自动去重。因此重复点击、重复发事件或读档后重新展示内容，不会发放重复奖励。

### 4.1 三个常用示例

调查模块：

```js
gameState = applyGameEvent(gameState, {
  type: GAME_EVENTS.OBJECT_INVESTIGATED,
  payload: {
    objectId: "shrine-bag",
    itemId: "personal-item-1"
  }
});
```

拼图模块：

```js
gameState = applyGameEvent(gameState, {
  type: GAME_EVENTS.MAP_PUZZLE_COMPLETED,
  payload: {
    puzzleId: "map-puzzle"
  }
});
```

剧情模块在拼图结束后切入老宅节点：

```js
gameState = applyGameEvent(gameState, {
  type: GAME_EVENTS.STORY_NODE_CHANGED,
  payload: {
    nodeId: "old-house-arrival",
    stageId: "old-house"
  }
});
```

`old-house-arrival` 需要剧情组确认后冻结；若剧情组采用其他节点 ID，应先通知全局负责人更新该约定。

## 5. 接入前检查清单

- [ ] 我从 `GAME_EVENTS` 使用事件常量，没有手写容易拼错的字符串。
- [ ] 我传入的 ID 是已约定的小写 kebab-case ID。
- [ ] 我使用 `gameState = applyGameEvent(...)` 接住了返回值。
- [ ] 我没有直接 `push()`、赋值修改状态字段或写游戏 `localStorage`。
- [ ] 我已处理失败提示，不让玩家点击后无反馈。
- [ ] 我需要新增事件、字段或 ID 时，先联系全局负责人。
