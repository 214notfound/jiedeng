# PR35 / PR36 移步换景组合审阅

## 第一部分：人必须看懂

**结论：PR #35 的移步换景主体正确；PR #36 提供了需要的阅读框、人物位置和地图碎片详情能力，但不能原样直接合入最新 `release-v2`。两者已经在隔离分支完成组合修正并通过全量测试。**

**最终交互保持不变：村口主场景点入口光点 → 进入子场景（不记进度）→ 点人物光点 → 进入统一阅读 → 真正读完后提交原 `NPC_TALKED` → 新取得的地图碎片打开详情。** 未读完关闭仍留在原子场景；阅读时热点和“返回村口”不可操作；详情关闭回到打开前的探索状态。

**没有新增 Host 接口、全局页面状态、剧情事实或存档字段。** `game-flow.js`、`game-page-controller.js`、剧情 Node、state 和 storage 均未修改。展示子场景仍是探索模块内的临时状态，不写入存档。

PR #36 原样叠加时有三项问题，已在组合结果中处理：

1. 与最新全局详情操作的清理代码在 `game-ui.js` 冲突；组合后同时保留忙碌/失败重试清理和阅读类型标记清理。
2. 人物层下移 2% 后，旧测试把“在裁切容器内微调”误判成越界；组合测试现在同时要求偏移不超过 3% 且舞台必须 `overflow:hidden`，确保可见内容不会伸出场景。
3. PR #36 会给所有新获得物品自动开详情，导致取得旧钥匙时打断原阅读链；组合后只有三张地图碎片带 `autoOpenOnAcquire`，旧钥匙继续原流程。

仍需人工确认一项视觉选择：**“返回村口”暂时保留在 PR #35 的场景上方。PR #36 没有给出公共顶栏方案，也没有明确要求移动。** 技术链路已经可用；若高冰轩要求移到公共顶栏，必须复用同一个返回回调并删除模块内按钮，不能出现两个返回入口。
