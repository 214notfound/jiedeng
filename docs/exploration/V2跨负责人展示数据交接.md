# V2 跨负责人展示数据交接

## 一、人需要先看懂的结论

> **可直接交付的数据已经齐：场景使用 `sceneId + sceneVariant + sceneImage`，物品详情使用 `itemId + detailImage`。页面只显示这些字段，不能读取剧情事实自行判断。**

> **`cunkou.png` 是村口 `su-he-notice`（苏禾寻人启事）的热点详情图，不是背包物品。它与仓库中的 `su-he-notice.png` 内容及 SHA-256 完全一致。**

> **老宅门由稳定字段 `sceneVariant` 控制：`door-closed` 显示关门图，`door-open` 显示开门图。该字段由探索模块根据已提交状态生成，页面不得检查热点、Node 或事实来猜。**

三张场景图均按 1280×720、16:9、`object-fit: contain` 显示，当前实现不裁切，热点与图片在同一坐标容器同步缩放。杨梦仍需最终确认“这些文件就是冻结版素材”；如果素材构图变化，需要重新验收坐标，不能只替换图片。

页面消费 `module.getSceneView(sceneId)`：

```js
{
  name: "陈家老宅",
  sceneId: "old-house",
  sceneVariant: "door-open",
  sceneImage: ".../old-house-door-open.png",
  interactions: []
}
```

`sceneVariant` 的生产规则属于探索模块：只有已提交状态包含 `old-house-door-opened` 时才输出 `door-open`，否则输出 `door-closed`。页面不得直接读取 `facts/storyCheckpoint`，也不得用 `old-house-door` 热点是否存在来判断。

## 三、边界与验收

- 探索模块只读取 Host 已提交的 `facts/inventory/clues/storyCheckpoint`，不写全局状态、不调用 `enterStory()`、不直接操作存档。
- 页面只消费 `sceneId/sceneVariant/sceneImage` 和详情条目，不读取剧情事实，不根据按钮文字、热点消失或 Node 推断展示。
- NPC 在探索态只显示发光点；点击后进入全局 `reading`，人物素材在独立人物层显示。背景图不常驻绘制人物。
- 场景、热点共用同一 16:9 坐标空间；当前使用 `contain`。若改为 `cover` 或替换构图，必须重新确认裁切偏移与全部热点。
- `detail`、`inventory`、`minigame` 由全局覆盖层锁住底层；详情的“×”、ESC、浏览器/Android 返回统一调用 `closeOverlay()`。
- 任何失败都不得伪造完成。Host 明确 `{ok:false}` 可重试；异常、结构不可信或成功未落账时维持保护锁。

## 四、尚需外部确认的一项

杨梦只需确认：当前四张 1280×720 场景文件（祠堂、村口、老宅门关、老宅门开）是否为冻结版，以及完整画布是否都属于可安全显示范围。若答案为“是”，本交接项关闭；若图片构图仍会改动，再按新图复核百分比坐标。
