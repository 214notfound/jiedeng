# 给高冰轩：V3 外围调查“阅读 → 探索”修复交接说明

## 1. 现场问题

进入 `outer-lines-investigation` 后，页面显示“四条线可以按任意顺序追查”的介绍，但读完后停在阅读层，看不到四个场景入口。

探索模块已经提供四个入口，断点位于全局页面状态：剧情响应同时包含介绍 `presentation` 和四个外部命令时，运行时状态为 `ready`；原页面只渲染介绍，没有在真实阅读完成后切换到 `exploration`。

## 2. 本次从全局模块修改的内容

### `assets/js/core/game-ui.js`

- `renderResponse` 增加可选的 `onComplete` / `onClose` 生命周期回调。
- 回调仍由统一阅读器在最后一个真实阅读块完成时触发。
- 没有伪造完成、没有让关闭操作冒充阅读完成。

### `assets/js/core/game-page-controller.js`

- 新增 `shouldEnterExplorationAfterReading(response)` 判定。
- 仅同时满足以下条件时自动进入探索页：
  1. 响应状态为 `ready`；
  2. presentation 的剧情 actions 为空；
  3. 响应中已有合法 `REQUEST_EXPLORATION`、`REQUEST_CONVERSATION` 或 `REQUEST_MINIGAME` 命令。
- 阅读完成时再次核对原响应的命令仍在当前 `activeCommands` 中，避免旧阅读回调切换已经过期的页面。
- 切换前调用统一阅读器 `close()` 清除临时阅读游标和 DOM 内容。
- 通过 `viewCoordinator.showBase("exploration")` 切换，不直接改 `hidden`、`inert` 或 CSS。
- 切换后将焦点交给第一个未禁用的 `.scene-hotspot`；没有可用热点时才回退到任意热点。

## 3. 明确未做的事情

- 未修改剧情 Node、revision、事实、命令和转移。
- 未由探索模块直接切换全局页面。
- 未让四个 Hub 入口发送 `OBJECT_INVESTIGATED`。
- 未改变背包、详情、小游戏覆盖层的返回栈。
- 未恢复存档中的旧 DOM、阅读游标或覆盖层。
- 未修改名字和线索文案。

## 4. 覆盖层、焦点与存档约束

本次继续以 `viewCoordinator` 作为唯一页面状态入口：

- 阅读态：场景可见但 inert，热点由现有 CSS 隐藏且不可点击；
- 探索态：故事面板隐藏，场景恢复交互；
- 背包/详情/小游戏：仍使用原覆盖层栈，不受本次分支影响；
- 读档：只依据已提交剧情响应和 pending commands 重建页面，不保存或恢复阅读进度。

## 5. 测试覆盖

- 有介绍、无剧情 action、存在外部命令 → 允许阅读完成后进入探索；
- presentation 仍有剧情 action → 不自动切换；
- 没有外部命令 → 不自动切换；
- ended 响应 → 不自动切换；
- 正式 `renderResponse` 的阅读完成回调只触发一次；
- 外围 Hub 四入口仍是纯导航，不改变探索业务 action。
