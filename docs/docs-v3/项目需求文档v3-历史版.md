# 《借灯》项目需求文档 V3

## 一、V3 核心目标与最终交付成果

复用 V2 已确定的页面、阅读、协调、状态、探索、对话、背包和成就逻辑，把《借灯》从现有的 `week-one-end` 连续推进到正式结局。

V3 主要增加后半段内容、场景、热点、对话和视听资源，再将这些内容接入已经存在的模块。

V2 目前尚未完全 release。V3 因此采用两条线并行推进：已经稳定的 V2 接口直接复用；尚未通过正式页面验收的 V2 功能继续收尾，并作为 V3 的前置问题记录。

最终交付成果包括：

1. 一份可从开场连续游玩到结局的 release-v3。
2. V3 共 28 个运行时 Node、四个后续剧情阶段和五个结局全部接入正式流程。
3. 后半段所需场景、热点、NPC 对话、线索、背包内容、成就、音乐和剧情展示全部可用。
4. 三个新增小游戏在剧情流程中有正式入口和结果回传。其中两个为解密风格，一个为追逐风格。本需求只安排剧情接入与结果联调，不安排具体玩法开发；若 release-v3 要作为完整可玩版本发布，需要另行指定小游戏玩法负责人。
5. 新游戏、继续游戏、切换界面、保存、恢复、失败提示和五条结局路径均通过正式页面验收。
6. 对 V2 遗留问题和 V3 新问题形成可复现、可归属、可复测的记录。



## 二、人类可读部分

### 2.1 玩家最终能玩到什么

玩家仍从祠堂醒来，经过村口和陈家老宅完成 V2 已有内容。老宅不再是整局游戏的终点，而是后半段调查的起点。

之后，玩家会按任意顺序调查陈晋年坠沟、王阙项目记录、苏禾失踪和白灯客材料四条外围线索，确认所谓闹鬼来自人工装置。调查继续深入后，玩家会依次确认主角是王阙、王阙就是陈晋年、白灯客也是同一个人，并重返矿井还原苏禾死亡的完整责任链。

终局中，小周要求回收证据。玩家可以直接交出证据，也可以拒绝并进入追逐。成功逃离后，还要在销毁证据、选择性公开和完整公开之间作出选择。五条路径分别进入五个稳定结局。

### 2.2 玩家如何操作

- 剧情旁白、系统提示和 NPC 对话都在统一阅读组件中显示。
- 场景调查通过点击热点完成。能否点击、点击后看到什么、是否已经完成，由探索模块和已提交状态共同决定。
- 线索与背包沿用 V2 的查看逻辑。点击条目打开详情，关闭后返回原界面。
- 需要打开阅读、详情、背包、小游戏或其他界面时，业务模块先向全局模块申请，不直接控制页面。
- 每次调查、谈话、选择或小游戏结束后，结果先经过全局协调与状态提交，再由剧情模块判断后续 Node。
- 保存和继续游戏必须回到真实进度。不能因为恢复失败就自动新建游戏，也不能把小游戏技术故障算成剧情失败。

### 2.3 特别说明
1. 小游戏的内容不设计，正常构造“进入->操作->退出”的流程，操作页面与操作方法极简即可；小游戏内容/成就内容/音效与可能的CG属于V4开发内容
2. 有别人的PR先集体审核，不要不管不顾自己PR上去，PR前先从release-v3中拉下来最新版看兼容
3. 协作的具体接口直接按照V2来，不做不必要的更改，尽量全部复用，因此本文没写具体接口，但是需要明确模块之间的请求与协作，比如什么情况，谁向谁发请求，如何回应等等

只要某条能力已经稳定，对应 V3 内容就可以开始接入。最终 release-v3 前，所有 V2 遗留阻断项都必须解决。

> 全局：
> 1. 切窗口：模块需要切窗口的时候要向全局发申请
> 2. 协调模块工作流：作为中转路由转发模块的请求与回复
>
> 状态：
> 1. 游戏状态存档：哪些地方需要存档，就需要哪些地方的接口，比如小游戏的状态如何存档，需要判断目前的策略是状态模块询问迷你游戏模块，还是询问剧情模块，问谁=问如何存档如何恢复=问这个模块是如何保存游戏状态的？什么字段？
>
> 前端游戏页面+阅读模块
> 1. 前端游戏页面复用：现有v2确定的页面复用，（内容填充）
> 2. 阅读：前端页面中应该存在阅读块，控制阅读块的展示与消失，内容由其他模块通过全局-协调传递
> 3. 玩家页面反馈
> 4. 焦点控制，各种界面的打开/关闭
> 5. 响应式与最终可读性
>
> 剧情模块：
> 1. 对齐v2终版的接口需求，明确哪些操作需要剧情提供信息，比如阅读需要提供对白示例，按钮需要提供action列表等等
> 2. 根据剧情扩写/缩写/改写现有的展示剧情（控制长度）
> 3. Node节点的确认，优先把新增部分比如Node节点交付其他模块
>
> 探索
> 1. 热点位置：对确定好的场景进行ID、坐标、热点等绑定
> 2. 调查点击：应该主要是js文件，处理探索中的点击命令，与页面控制沟通进行展示（逐页面考虑，一个页面几个需要点击的图？叫什么？然后再写逻辑）
> 3. NPC对话：自己设计即可，向阅读组件提交内容文本，向剧情板块确认里程碑完成情况
> 4. 线索与背包：依然是点击->展示->点击->关闭的逻辑，页面由页面模块负责，点击指令也是页面发送，内容本模块控制即可
>
> 整体功能集成：
> 1. 负责最后一版release-v3，测试bug，有问题直接录屏发群里，判断是哪个/哪两个/哪些模块直接出现了问题，解决
>
> 美术、视觉与听觉
> 1. 场景：先定场景的结构（坐标根据结构美术模块定），在定背景
> 2. 视觉校验
> 3. 每个Node之间挑选背景音乐（可以重复），入口登陆，成就，项目组部分都要有音乐

## 四、模块功能与协作要求

### 4.1 全局协调模块

#### 功能一：统一切换窗口

任何模块需要打开或关闭阅读、探索、详情、背包、小游戏界面时，都先向全局模块提出申请。全局模块判断当前是否允许切换，再通知页面模块执行。

协作顺序：

1. 页面模块先交付现有 V2 容器清单和可切换状态。
2. 剧情、探索、对话、背包和小游戏模块分别说明自己在什么时机需要打开、关闭或返回。
3. 全局模块统一处理申请，页面模块只执行全局确认后的结果。
4. 页面模块验证焦点、背景锁定和关闭后的返回位置。

业务模块不得直接操作其他模块的窗口，也不得根据按钮文字猜测应该切到哪里。

#### 功能二：协调模块工作流

全局模块是中转路由。玩家在页面产生操作后，全局模块把请求交给对应业务模块；业务模块返回结果后，全局模块再交给状态或剧情处理，并把最终回复送回页面。

剧情、探索、对话和小游戏之间原则上不直接互调。比如 NPC 对话完成后，由对话模块把结果交给全局，再由全局交给状态和剧情；对话模块不能直接修改剧情进度。

全局模块先提供一条真实的 V3 请求转发样例。剧情、探索和页面模块分别确认自己能收到完整请求与回复后，再扩展到全部 Node。

#### 功能三：错误路由与重复操作保护

连续点击、模块取消、加载失败和状态提交失败都由全局模块统一安排返回路径。技术详情写入控制台，页面只显示玩家能理解的提示。

出错时保持旧状态，不提前关闭窗口，不提前显示完成，也不把同一次操作重复提交。

### 4.2 状态与存档模块

#### 功能一：游戏状态提交

状态模块继续作为正式状态的唯一提交方。探索、对话、剧情选择和小游戏只提出结果，状态模块确认结果合法并完成提交后，剧情才能继续判断下一 Node。

协作顺序：

1. 剧情模块先交付新增 Node 的完成目标和结果含义。
2. 探索、对话和小游戏模块说明哪些玩家操作会产生这些结果。
3. 状态模块确认保存范围和提交时机。
4. 全局模块把提交后的状态交回剧情模块，再把新页面结果发送给页面模块。

#### 功能二：保存与恢复

状态模块需要向“拥有该状态含义的模块”询问如何保存和恢复，不能把所有问题都问剧情模块。

| 需要保存的内容 | 状态模块向谁确认 | 原因 |
| --- | --- | --- |
| 当前剧情位置、等待中的外部任务 | 剧情模块 | 剧情模块知道 Node 与检查点如何恢复 |
| 已调查热点、已完成谈话、线索和背包结果 | 探索模块 | 探索模块知道内容完成后怎样重建场景和详情 |
| 小游戏是否完成、是否需要保存中途进度 | 对应小游戏模块 | 小游戏模块才知道内部局面如何序列化和恢复 |
| 当前打开的页面和返回焦点 | 全局与页面模块 | 这是界面恢复问题，不属于剧情内容 |
| 已解锁成就 | 成就模块 | 成就模块负责根据已提交结果恢复展示 |

V3 默认沿用 V2 的简单策略：地图拼图只保存是否完成，不保存中途布局。三个新增小游戏若没有提供稳定的中途恢复方案，也只保存“未完成或已完成”，读档后未完成的小游戏从入口重新开始。任何模块若要求保存中途状态，必须先向状态模块说明保存内容、恢复时机和版本不兼容时的处理方式。

#### 功能三：旧存档兼容

V3 必须支持从 V2 的 `week-one-end` 继续后半段调查。剧情模块先提供迁移规则，状态模块负责在真实存档流程中验证；未知版本和缺失状态必须明确报错。

状态模块不得猜测缺失剧情，也不得替玩家补选结局。恢复失败时保留原存档和返回入口。

### 4.3 游戏页面与统一阅读组件

#### 功能一：复用 V2 游戏页面

V3 继续使用现有正式游戏页面和 V2 已确定的容器。新增工作以内容填充为主，不另建一套 V3 游戏页。

剧情、探索和美术模块先交付新增内容需要的页面类型；页面模块确认现有容器能承载后再接入。确实无法承载时，只增加必要容器，不重构无关区域。

#### 功能二：统一阅读

页面中保留统一阅读块，用于显示剧情旁白、系统提示和 NPC 对话。内容分别由剧情模块或探索中的对话功能提供，经全局协调后送入阅读组件。

阅读组件只负责按顺序展示、控制继续、关闭和末尾回调。它不修改事实，不判断对话是否完成，也不决定下一 Node。

协作顺序：剧情模块先交一段 V3 剧情样例和一段人物对白格式样例，用来确认阅读组件能显示哪些内容和操作；探索模块再交一段正式 V3 NPC 对话。页面模块分别跑通后，全局模块确认两类末尾回调都回到正确业务模块。

#### 功能三：玩家页面反馈

保存成功、没有存档、存档损坏、操作失败、内容尚未完成、资源加载失败等情况，都要有玩家可理解的反馈。含义由发现问题的业务模块提供，显示位置和交互由页面模块负责，全局模块负责路由。

内部 ID 和异常对象只进控制台。正式页面不得把开发信息直接当成提示文本。

#### 功能四：焦点和界面开关

阅读、详情、背包或小游戏打开后，背景热点和 NPC 不得继续接收点击。关闭覆盖层后，焦点回到打开前的有效位置；若剧情已经推进，则以全局模块返回的新界面为准。

页面模块先完成界面锁定，全局模块再验证切换顺序，探索模块负责验证热点没有穿透。

#### 功能五：响应式与最终可读性

页面至少在 V2 已确定的目标宽度下完成检查。新增场景、长文本、结局标题、选项按钮、线索详情和小游戏入口都不能横向溢出或遮挡关键对象。

杨梦检查构图、对比度和素材裁切；高冰轩检查容器、文字和焦点；卢正松检查热点与实际对象仍然对应。

### 4.4 剧情模块

#### 功能一：对齐 V2 的模块需求

剧情模块继续通过全局模块向页面提供阅读内容和可执行操作，向探索、对话和小游戏提供当前任务及完成目标。其他模块只把结果送回，不向剧情模块索要具体玩法或页面布局。

剧情模块需要先整理哪些 Node 会显示阅读内容、哪些 Node 会等待探索、对话或小游戏、哪些 Node 会要求玩家选择。清单中同时给出阅读样例和玩家可执行操作列表。这个清单先交给全局、页面和探索模块，是 V3 其他内容开工的第一份上游交付。

#### 功能二：调整展示剧情

杨梦根据完整故事大纲，对现有展示内容进行扩写、缩写或改写。原则是每个 Node 只保留推动理解和选择所需的内容，不把完整大纲直接搬进阅读组件。

单次阅读长度需要与页面模块共同试读。页面装不下时，剧情模块负责拆分阅读内容，页面模块负责分页显示；不能通过缩小字号解决所有长文本问题。

NPC 具体对白仍由探索模块负责。剧情模块只确认谈话必须完成的剧情目标，并在对话稿完成后检查有没有提前泄露身份或遗漏关键责任。

#### 功能三：确认和交付 Node

新增 Node、阶段顺序、外部任务、选择和五个结局以 [V3剧情Node推进.md](./game-line/V3剧情Node推进.md) 为准。技术 ID 一旦交给其他模块使用，不因改文案而更换。

交付顺序：

1. 先交 28 个 Node 的展示、等待和分支清单。
2. 再交四段新增阶段各自需要的场景、探索任务、谈话和小游戏入口。
3. 页面、探索和全局确认能够接入后，补齐最少量正式展示文本。
4. 五条结局全部接入后，剧情模块执行顺序回归和姓名、泄露时点检查。

人物显示名统一为陈晋年、王阙和小周。工作证开场只揭示王姓，村民称“王工程师”，完整姓名王阙在身份揭示 Node 才确认。旧技术 ID 保持不变。

### 4.5 探索、NPC 对话、线索、背包与成就模块

#### 功能一：场景热点位置

剧情模块先给出每个阶段要调查什么和需要哪些场景。探索模块据此列出场景中的对象和 NPC；杨梦先确定场景结构与关键物体位置，高冰轩确认页面容器的缩放和裁切方式，卢正松最后绑定对象 ID、坐标和热点范围。

顺序不能倒置。背景构图尚未冻结时，不批量写最终坐标；容器缩放规则尚未确认时，不用单一屏幕截图估算百分比位置。

#### 功能二：调查点击

探索模块按场景逐页实现点击逻辑。每个页面先列出可点击图片或人物、玩家看到的名称、出现条件、点击后打开的内容以及完成后应消失还是保留。

玩家点击由页面发送，经全局路由到探索模块。探索模块处理业务结果；需要展示时向全局申请打开阅读或详情；玩家关闭或确认后，再由全局继续转发状态提交和剧情判断。

先跑通一个 V3 场景的一条完整点击链，再扩展同场景其他热点，最后复制到全部新场景。

#### 功能三：NPC 对话

卢正松可以自行设计具体对白，但必须先向剧情模块确认本次谈话要完成什么、哪些信息不能提前说。对话内容经全局交给统一阅读组件，阅读结束后再把完成结果送回全局。

剧情模块负责确认里程碑是否成立；对话模块不得因为文本播放结束就自行跳到下一 Node。对话需要扩展时，只增加内部内容，不改变已经约定的剧情目标。

#### 功能四：线索与背包

线索和背包继续使用“点击条目、打开详情、确认或关闭、返回原界面”的 V2 逻辑。页面和焦点由高冰轩负责，条目内容、分类和点击结果由卢正松负责，正式状态由状态模块保存。

新增线索只有在状态提交成功后才显示为已获得。重复查看不重复产生奖励，恢复存档后不重新弹出首次获得效果。

#### 功能五：成就

成就模块根据已提交的剧情、探索和结局结果判断解锁，不监听临时按钮，也不抢先读取尚未提交的候选结果。

剧情模块先给出适合触发成就的稳定剧情节点或结局含义；卢正松设计成就内容；高冰轩负责页面展示；杨梦提供视觉和音乐需求。成就展示失败不能回滚剧情进度。

### 4.6 整体功能集成

#### 功能一：组装 release-v3

卢正松负责最后一版 release-v3 的整体组装和测试组织。各模块必须先完成独立验证，再进入候选版本；集成阶段不接收只有 demo 可用、正式页面不可用的交付。

推荐集成顺序：

1. 先确认 V2 从开场到老宅仍可运行。
2. 接入 V3 剧情 Node 和全局路由。
3. 按阶段接入场景、热点、对话、阅读内容和音乐。
4. 接入小游戏入口、状态结果、保存与恢复。
5. 接入五条结局、成就和最终反馈。
6. 形成候选版本并执行完整回归。

#### 功能二：问题记录与归属

测试发现问题时，直接录屏发到项目群，并同时写清入口、操作步骤、预期结果和实际结果。卢正松先判断问题属于一个模块，还是两个以上模块的交接处，再通知对应负责人。

常见归属如下：

| 现象 | 优先检查模块 |
| --- | --- |
| 窗口不切换、重复打开、关闭后回错位置 | 全局与页面 |
| 保存后 Node、热点或背包状态不一致 | 状态与对应业务模块 |
| 剧情顺序、选项、结局错误 | 剧情与全局 |
| 热点点不到、点错对象、重复结算 | 探索；位置漂移时加页面或美术 |
| 对话提前结束、内容泄露或完成后不推进 | 探索对话与剧情 |
| 背景裁切、文字不清、音乐错误 | 美术、页面或听觉配置 |
| 单模块正常，串联后失败 | 整体集成牵头，调用链上的相关模块共同复现 |

修复后由最初报告问题的人沿同一条路径复测。只说“我这里没问题”不能关闭问题。

### 4.7 美术、视觉与听觉模块

#### 功能一：场景结构与背景

剧情模块先给出 Node 所需地点和调查目标，探索模块列出必须出现在画面中的对象与 NPC。杨梦根据这些内容先画场景结构或低清草图，标明关键对象和文字安全区；卢正松确认对象可绑定热点，高冰轩确认页面裁切后，杨梦再制作正式背景。

坐标以冻结后的构图和正式页面容器为准。背景替换不得随意移动已经绑定的关键对象。

#### 功能二：视觉校验

杨梦在正式页面检查场景裁切、阅读区遮挡、热点可辨识度、文字对比度、结局画面和成就展示。素材问题由杨梦修，容器和字体问题交高冰轩，热点范围问题交卢正松。

每次检查都要基于正式页面截图，不能只看单张原图。

#### 功能三：背景音乐

杨梦为每个 Node 或连续 Node 段选择背景音乐，相邻 Node 可以复用。音乐表至少覆盖登录入口、游戏主流程、三个新增小游戏入口、五个结局、成就页面和项目组展示部分。

剧情模块先给出每段的情绪与切换点，杨梦完成音乐选择，卢正松在整体集成中接入，高冰轩检查页面切换、暂停和重复播放表现。音乐加载失败时游戏仍应可继续，并给出非阻断反馈。

## 五、模块交付顺序

| 阶段 | 先交付模块 | 后续模块 | 本阶段完成标志 |
| --- | --- | --- | --- |
| 0. V2 基线确认 | 全局、状态、页面、探索 | 剧情、美术 | V2 最小链在正式页面可复现，遗留问题有归属 |
| 1. V3 内容清单 | 剧情 | 全局、页面、探索、美术 | 28 个 Node 的展示、等待、分支和场景需求明确 |
| 2. 场景与阅读样例 | 剧情、探索、美术 | 页面、全局 | 一个新场景、一段剧情和一段 NPC 对话能正式显示 |
| 3. 第一段后续流程 | 全局、状态、页面、探索 | 整体集成 | 老宅可进入外围四线，完成后不重复结算 |
| 4. 身份与矿井流程 | 剧情、探索、美术、听觉 | 页面、状态、整体集成 | 两个解密入口、身份揭示和矿井证据链可连续完成 |
| 5. 终局与五结局 | 剧情、小游戏结果、状态 | 页面、成就、整体集成 | 交证、追逐失败及三种公开选择都进入正确结局 |
| 6. release-v3 | 整体集成 | 全体复测 | V2 遗留阻断项关闭，完整路径、存档和视听验收通过 |

模块交付以“使用方能在正式调用链中跑通”为完成标准。文件已经提交但下游无法调用，不算交付完成。

## 六、release-v3 验收标准

- [ ] V2 的祠堂、村口、老宅流程仍可连续完成，原地图拼图行为不变。
- [ ] `week-one-end` 可以继续进入 V3，旧存档迁移失败时有明确反馈且不损坏原档。
- [ ] 28 个 Node 均可到达，四个后续阶段顺序正确。
- [ ] 外围四条调查线可按任意顺序完成，完成后不重复提交或重复奖励。
- [ ] 剧情、NPC 对话、线索详情均使用同一个阅读组件，末尾不会重复回调。
- [ ] 两个解密入口和一个追逐入口能正确返回结果；技术故障不会进入剧情失败结局。
- [ ] 交出证据、追逐失败、销毁、选择性公开、完整公开五条路径分别进入正确结局。
- [ ] 探索、对话、小游戏和页面都不能自行修改下一 Node。
- [ ] 保存和继续游戏能恢复剧情位置、待办任务、已调查热点、线索、背包、成就及小游戏完成状态。
- [ ] 覆盖层打开时没有背景点击穿透，关闭后焦点与界面恢复正确。
- [ ] 正式页面文字可读，没有横向溢出、关键对象遮挡或技术字段泄露。
- [ ] 登录入口、游戏流程、小游戏、结局、成就和项目组部分均有合适音乐；音频失败不阻断游戏。
- [ ] 每个阻断问题都有录屏或清晰复现记录、明确负责人和修复后的原路径复测。

V3 的剧情结构和外部任务以 [V3剧情Node推进.md](./game-line/V3剧情Node推进.md) 为准；V2 已确定的页面和协作原则继续参考 [项目需求文档v2.md](./项目需求文档v2.md) 与 [V2开发执行路线.md](./V2开发执行路线.md)。三份文档发生冲突时，V3 的目标、分工和交付顺序以本文件为准，底层接口仍以已经通过联调的现有实现为准。
