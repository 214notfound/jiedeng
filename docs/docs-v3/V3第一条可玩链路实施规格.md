# V3 第一条可玩链路实施规格

- **版本：** 1.0
- **状态：** 等待全局 / 状态接口确认和正式场景图
- **实现负责人：** 卢正松
- **联调负责人：** 高冰轩
- **视觉交付：** 杨梦
- **适用基线：** `release-v3`（包含 PR #56）

## 1. 本规格解决什么

第一条正式样例固定为：

`week-one-end@2` → `outer-lines-investigation` → 外围调查 Hub → `mountain-routes` → `investigate-gorge-and-grave`

这条样例必须在正式 `pages/game.html` 中运行。测试夹具、调试按钮或独立 demo 能运行，不算完成。

首个样例只提交陈晋年山沟与衣冠冢一线的完成事实，不要求同时完成外围其余三线；因此完成后仍停留在 `outer-lines-investigation`，等待其他三条调查。

## 2. 规则优先级

发生冲突时按以下顺序执行：

1. 已通过联调的公共 V1 运行时合同；
2. `V3剧情Node推进.md` 中的 V3 新增事件和事实要求；
3. `《借灯》项目需求文档 V3.md` 的页面、状态、存档和分工约束；
4. `V3接口契约.md` 的交接表；
5. 草图和口头说明。

`V3接口契约.md` 中“探索直接回报 `STORY_FACT_RECORDED`”是交接层简写。正式运行时不得由探索模块直接写状态；探索模块应发送 `OBJECT_INVESTIGATED`，剧情模块再在 commit 中产生正式状态事件。

## 3. 已冻结字段

| 字段 | 固定值 | 所属方 |
| --- | --- | --- |
| Node | `outer-lines-investigation` | 剧情 |
| Node revision | `1` | 剧情 |
| stageId | `outer-investigation` | 剧情 |
| Hub sceneId | `outer-investigation-hub` | 探索 / 页面待确认 |
| 子场景 sceneId | `mountain-routes` | 剧情 / 美术 |
| targetId | `investigate-gorge-and-grave` | 剧情 |
| goalId | `gorge-thread-complete` | 剧情 |
| 完成 factId | `a-gorge-thread-complete` | 剧情 |
| capability | `exploration` | 剧情 |
| commandId | `cmd-outer-lines-investigation-investigate-gorge-and-grave` | 运行时生成规则 |
| 建议首版 actionId / objectId | `investigate-gorge-and-grave` | 探索；见第 6 节 |

除 `Hub sceneId` 和首版 `actionId/objectId` 外，其余字段均已由剧情数据冻结，不得在探索实现中改名。

## 4. Hub 与子场景规则

`outer-lines-investigation` 会同时发出四个 `REQUEST_EXPLORATION`。因此第一条样例不能把整个 Node 简单映射成一张山沟背景，否则另外三条命令没有合法入口。

正式页面应先显示外围调查 Hub，包含四个导航入口：

| 导航入口 | targetId | 子场景建议 | 首批状态 |
| --- | --- | --- | --- |
| 山沟与衣冠冢 | `investigate-gorge-and-grave` | `mountain-routes` | 正式可玩 |
| 工程档案 | `investigate-project-records` | `project-records` | 保留入口，等待后续接入 |
| 苏禾轨迹 | `investigate-su-trail` | `su-trail` | 保留入口，等待后续接入 |
| 白灯通信 | `investigate-white-lamp-mail` | `white-lamp-mail` | 保留入口，等待后续接入 |

Hub 入口只是页面导航：

- 不发送 `OBJECT_INVESTIGATED`；
- 不提交事实；
- 不完成剧情目标；
- 返回 Hub 时不丢失正式命令；
- 读档后恢复到安全基础页时，可以回到 Hub，但不得自动重开子场景或阅读层。

未接入的三条线应显示玩家可理解的“该调查点尚未开放”状态，不得显示内部 ID，也不得伪造完成结果。

## 5. 剧情命令输入

探索模块只接收当前检查点中仍有效的正式命令：

```js
{
  commandId: "cmd-outer-lines-investigation-investigate-gorge-and-grave",
  commandType: "REQUEST_EXPLORATION",
  payload: {
    explorationId: "investigate-gorge-and-grave",
    goals: [{
      goalId: "gorge-thread-complete",
      description: "确认陈晋年的坟中无遗体，并取得邻镇诊所线索。"
    }]
  }
}
```

探索模块不得根据按钮文字、场景名称或当前 URL 猜测 targetId。

## 6. 第一版交互内容

### 6.1 首版采用一个聚合调查热点

为避免在尚未登记中间事实时出现“点击第一个物体就提前完成整条线”，第一版采用一个聚合热点：

| 字段 | 值 |
| --- | --- |
| actionId | `investigate-gorge-and-grave` |
| objectId | `investigate-gorge-and-grave` |
| 玩家名称 | 调查山沟与衣冠冢 |
| marker | 山沟与衣冠冢 |
| interactionType | `item` |
| resultFactIds | `a-gorge-thread-complete` |

聚合热点需要依次讲清：

1. 送葬路线与当年搜救路线重合；
2. 浅沟、深排水洞证明兄妹并非停在同一落点；
3. 妹妹为实葬，陈晋年只有衣冠冢，坟中没有遗体；
4. 搜救三日后由父亲签字终止，并留下邻镇诊所票据编号；
5. 小周对票据编号表现出过度关注并催促离开；
6. 归档结论：陈晋年的死亡只是村庄结论，邻镇诊所是下一条身份线索。

不得在这条调查中提前确认“陈晋年就是王阙”或“主角就是王阙”。

### 6.2 后续拆成多个热点的条件

若产品决定把山沟、衣冠冢和管理夹层拆成多个独立热点，必须先由剧情、状态和探索三方共同登记中间事实及完成条件。不能只在 DOM 或内存中记录三次点击，因为刷新和读档后无法可信恢复。

在中间事实尚未冻结前，不把多个物体都绑定到 `a-gorge-thread-complete`；否则第一次点击就会使整条 handoff 完成，其余内容被跳过。

## 7. 阅读与提交时序

正确顺序固定为：

1. 玩家进入 `mountain-routes`；
2. 点击“调查山沟与衣冠冢”；
3. 探索模块向全局申请打开统一阅读；
4. 统一阅读按顺序显示第 6 节内容；
5. 玩家真实读到末段并确认；
6. 探索模块发送一次 `OBJECT_INVESTIGATED`；
7. 状态模块校验并建立候选状态；
8. 剧情模块确认 `gorge-thread-complete` 成立并生成正式 commit；
9. 全局提交成功后刷新场景；
10. 返回 Hub 或当前探索基础页，另外三条外围命令仍然存在。

当前 V2 探索代码是“先提交事实，再打开阅读”。V3 第一条样例需要调整为“阅读完成后提交”，但仍必须复用现有统一阅读组件，不能新建第二套阅读弹窗。

## 8. 正式结果事件

```js
{
  eventId: "evt-cmd-outer-lines-investigation-investigate-gorge-and-grave-investigate-gorge-and-grave-object_investigated",
  eventType: "OBJECT_INVESTIGATED",
  source: "exploration",
  causedByCommandId: "cmd-outer-lines-investigation-investigate-gorge-and-grave",
  resultFactIds: ["a-gorge-thread-complete"],
  payload: {
    objectId: "investigate-gorge-and-grave"
  }
}
```

约束：

- 不携带 `nextNodeId`、`currentNodeId` 或任何转移目标；
- `resultFactIds` 无重复，只包含当前 handoff 允许的事实；
- 同一完成操作只能有一个稳定 eventId；
- 已完成后回看内容不得再次提交；
- 明确失败后保留原检查点并允许重试；
- 结果不确定时停止后续提交，要求重新进入，避免重复记账。

## 9. 失败与取消

取消：

```js
{
  eventType: "EXTERNAL_INTERACTION_CANCELLED",
  source: "exploration",
  causedByCommandId: "cmd-outer-lines-investigation-investigate-gorge-and-grave",
  resultFactIds: [],
  payload: { targetId: "investigate-gorge-and-grave" }
}
```

技术失败：

```js
{
  eventType: "EXTERNAL_INTERACTION_FAILED",
  source: "exploration",
  causedByCommandId: "cmd-outer-lines-investigation-investigate-gorge-and-grave",
  resultFactIds: [],
  payload: {
    targetId: "investigate-gorge-and-grave",
    errorCode: "SCENE_RESOURCE_FAILED"
  }
}
```

取消和失败均不得携带事实，不得推进 Node。技术详情写控制台，玩家只看到可理解的重试提示。

- 人物如需出现，作为独立人物层交付；

## 11. 存档与恢复

完成前读档：

- 恢复 `outer-lines-investigation` 和四个待办命令；
- 回到外围调查 Hub 或合法探索基础页；
- 不自动重开 `mountain-routes`、阅读层或旧焦点；
- 玩家可以重新开始本次阅读。

完成后读档：

- `a-gorge-thread-complete` 保留；
- 山沟线命令不再发出；
- 山沟线显示已完成并允许回读，但不重复提交；
- 其余三条命令继续存在。
