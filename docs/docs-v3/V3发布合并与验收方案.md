# V3 发布合并与验收方案

## 1. 目标与基线

- 唯一集成目标分支：`release-v3`。
- 本轮冻结基线：`fa895c4`（PR #61 合并后）。
- 最终流向：`功能/修复分支 -> release-v3 -> main`。
- `main` 在 V3 发布验收完成前不直接接收 V3 功能提交。

## 2. V3 范围边界

允许进入本轮发布线的内容：

- V3 剧情扩展、28 个正式 Node 与 5 个结局。
- V3 场景资源、探索热点、分层场景与阅读转探索流程。
- V3 小游戏入口、结果契约及正式页面接入。
- V3 登录界面、音频接入、顶栏和正式游戏页视口布局。
- 为上述内容新增的测试、验收记录和必要文档。

禁止借本轮发布重新引入的内容：

- V1/V2 历史分支整体合并。
- 与 V3 正式流程无关的重构、改名或目录迁移。
- 调试入口、演示页面能力或玩家可见的内部 Node/事件字段。
- 未经过契约测试的新状态字段、新事件类型或跨模块接口。

如 V3 修复必须接触共享代码，应满足：改动最小、理由可追溯、V1/V2 回归测试全部通过。

## 3. 当前合并盘点

截至冻结基线，以下现代开发线均已包含在 `release-v3`：

- V3 剧情、全局状态和正式入口。
- V3 探索、场景坐标及完整结局链路。
- 登录页 V3 视觉修复。
- 音频基础设施、跨页面续播和静音控制。
- 顶栏全宽、游戏页铺满视口及移动端溢出修复。

`about`、`feature-v1`、`release-v1` 属于早期历史分叉，不作为待合并分支；其中有效补丁已经等价存在于后续版本。

## 4. 开发与合并流程

1. 每个新问题从最新 `origin/release-v3` 建立独立短分支。
2. 一个分支只处理一个可验收问题，避免夹带无关整理。
3. 修复必须附带最小回归测试；纯视觉调整至少增加布局契约或浏览器验收项。
4. 提交前运行受影响模块测试，再运行全量测试。
5. PR 目标只能是 `release-v3`，说明中列出修改范围、测试证据和 V1/V2 兼容性结论。
6. 合入后重新从 `release-v3` 运行发布门禁，不能复用功能分支上的旧结果。

## 5. 自动化门禁

必须全部通过：

- Node 全量测试零失败。
- V3 28 个 Node 预检通过，5 个结局均可达。
- V3 场景资源存在、唯一且尺寸契约正确。
- 正式 `game.html` 按规定顺序加载 V3 数据和运行时脚本。
- 顶栏保持全宽，不恢复旧版 `1440px` 居中限制。
- `html`、`body`、`.game-shell`、`.game-layout` 形成完整动态视口链路。
- 390px、768px、1280px 三类视口无横向溢出。
- 玩家界面不显示 Node ID、命令 ID、事件类型或原始异常。

## 6. 浏览器验收矩阵

### 入口与账户

- 封面进入主菜单。
- 游客进入、登录进入和无会话重定向。
- 新游戏、继续游戏、返回菜单。

### 顶栏与视口

- 顶栏横向占满可用宽度，标题和操作区顺序正确。
- 窄屏允许按既定规则换行或横向容纳，不遮挡主要内容。
- 游戏主体占满剩余视口，不出现页面级意外滚动。
- 音频按钮状态、静音切换与跨页面续播正确。

### 正式 V3 流程

- 阅读、探索、背包、详情、小游戏五类页面状态可切换并正确返回。
- 外围四线可以任意顺序完成。
- 三个 V3 小游戏只接受约定结果。
- 保存和读档后恢复当前命令，不重复发放事实或奖励。
- 至少完成一条完整公开结局，并抽查其余四个结局入口。

### 运行质量

- 正式资源无 404。
- 控制台无未处理异常。
- 键盘焦点不会进入隐藏覆盖层或隐藏热点。
- 缺图、存储失败和非法操作显示玩家可理解的反馈。

## 7. 缺陷分级与处理

- 阻断：无法进入正式游戏、流程不能推进、存档损坏、资源大面积缺失。必须修复后重新跑全部门禁。
- 严重：某一 V3 分支、小游戏、结局或移动端布局不可用。必须修复后重跑相关链路和全量测试。
- 一般：局部视觉、措辞或非关键焦点问题。评估风险后修复，但不得扩展到 V1/V2 重构。

## 8. 发布与回退

- 发布候选以明确的 `release-v3` 提交哈希为准。
- 验收记录包含测试数量、浏览器视口、完整流程结果和已知限制。
- 最终只通过 PR 将 `release-v3` 合入 `main`。
- 若合入前发现问题，从发布基线建立修复分支；不重写 `release-v3` 历史。
- 若合入后发现阻断问题，优先提交最小修复；需要回退时以合并提交为单位处理。
