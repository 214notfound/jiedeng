# V3 运行时桥接阻断清单

- **版本：** 1.0
- **检查基线：** 本地 `V3-exploration` at `66dc17a`，并核对远端已合并 PR #56
- **目的：** 在第一条正式 V3 探索链编码前，明确公共运行时必须补齐的能力和责任边界

## 1. 当前结论

PR #56 已把五个 V3 剧情脚本按正确顺序接入远端 `release-v3`，但只解决“正式页面加载剧情数据”。V3事实、场景、小游戏、存档和页面路由还没有全部接入公共运行时。

因此目前是：

- V3剧情骨架可在隔离测试中运行；
- 正式页面可以加载V3剧情脚本；
- 14个V3业务 handoff 尚无一个在正式页面完成实现；
- 不能把“28个Node测试通过”等同于“V3正式可玩”。

## 2. 阻断项与归属

| 编号 | 阻断项 | 当前证据 | 建议负责人 | 第一条链影响 |
| --- | --- | --- | --- | --- |
| B01 | 公共事实表没有V3事实 | `assets/js/core/game-contract.js` 仅登记V1事实 | 高冰轩主责，剧情确认，卢正松提供对象映射 | 状态会拒绝 `a-gorge-thread-complete` |

## 3. 第一条链开始编码前必须关闭

必须先关闭：B01、B02、B04、B05、B06、B07、B08。

B03、B09 可以在第一条纯探索样例之后关闭，但必须在 `haunting-network-puzzle` 开工前完成。B10 按场景逐批关闭，不要求第一条样例前一次补齐全部内容。

## 6. 完成判定

公共桥接完成不能只看文件是否存在，应满足：

- 正式页面初始化得到28个Node和5个结局；
- `week-one-end@1` 的旧存档能够安全迁移到 `@2`；
- 正式状态模块接受合法V3事实、拒绝未知或越权事实；
- 保存V3事实后能够重新加载；
- 四个外围命令同时存在时探索模块不会崩溃；
- 一个目标完成后只移除对应命令；
- 失败、取消和重复事件均不产生重复状态；
- 页面和玩家反馈不泄漏技术字段。
