# V3 全场景热点审查

- 审查日期：2026-09-13
- 审查基线：`V3-exploration`，已包含 PR57
- 审查范围：正式场景图片、探索/NPC 热点百分比坐标、场景投影、阅读态可见性
- 不在本次范围：名字和线索文案、图片重绘、具体小游戏内部机关

## 1. 审查规则

1. 热点使用 16:9 场景坐标空间中的百分比坐标，不用屏幕像素，也不根据移动端另建坐标。
2. `objectId`、`targetId`、`goalId`、`factId` 不因视觉校准而改变。
3. 导航入口只切换子场景，不发送外部完成事件；真正调查完成后才提交事实。
4. 阅读、详情、背包和小游戏打开时，探索热点必须不可交互；回到探索页后才恢复。
5. 热点中心应落在可辨认对象或约定安全区内，并在桌面端与 390px 裁切下保持可用。

## 4. 发现但未擅自扩展的事项

### 4.1 V3 多数调查仍是“单个聚合热点”

V3 图片中画出了多个证据对象，但当前剧情每条只发布一个 `REQUEST_EXPLORATION` handoff；现实现使用一个聚合热点打开完整调查阅读，并在全部内容读完后一次提交完成事实。

该实现满足当前事件契约，但不等于“每件画面物证都能分别点击”。如果产品要求逐个点击，需另开任务设计 handoff 内部进度：各局部热点只能记录临时 UI 进度，最后一个完成后才允许向剧情提交一次约定事实，不能为每张纸新增未经登记的 fact。

### 4.2 父亲旧屋暗层需要下一轮视觉确认

环境层入口坐标准确；进入暗层后，目前复用同一聚合 action。暗层有八张证据纸，如果未来拆成逐项热点，需要按 F01–F08 单独确定点击区。本次未擅自拆分接口。

### 4.3 仍需真实浏览器验收

静态图片与百分比坐标已经核对，自动化契约也已覆盖；仍需在桌面端和 390px 真机/浏览器确认：

- 44px 点击区是否被裁切；
- 阅读关闭后的首个热点焦点是否可见；
- 右边缘的身高刻痕和送葬名单是否出现横向溢出；
- 完成态透明度是否仍能看清热点；
- 四入口在介绍读完前不可点击、读完后同时出现。
