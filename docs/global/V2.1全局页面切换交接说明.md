# V2.1 全局页面切换交接说明

> 负责人：罗晨菲（全局板块）  
> 本轮范围：只负责页面怎么打开、怎么锁住、怎么返回，不修改页面样式、NPC 对话内容、热点数据和探索规则。

## 一、先说人话：玩家实际会感受到什么

我把全局页面切换当成游戏里的“交通指挥”。玩家点了什么，由对应模块告诉全局；全局只负责把玩家带到正确的界面，并保证返回时不会走错。

玩家探索时，场景和热点可以操作。点击 NPC 后，游戏进入阅读状态；场景还可以留在后面，但热点不能继续被点，避免玩家一边对话一边误触调查。点击物品后，游戏可以打开详情层；详情关闭后，玩家回到刚才的探索位置，而不是跳回菜单或丢失进度。

背包、详情和地图都是盖在当前画面上面的临时界面。全局会记住它们是从哪里打开的：从探索打开就回探索，从阅读打开就回阅读，从背包打开详情就先回背包。底下虽然还能看见，但不能点击，这样不会出现一次操作同时触发两个模块的情况。

我这次补了两个全局保障：

1. 每次切换页面时，把当前状态明确写在游戏主区域上。页面同学可以准确知道现在是阅读、探索还是详情状态，再显示对应布局，不需要通过“哪个元素碰巧显示着”来猜。
2. 玩家在详情界面按 ESC 时，和点击关闭按钮走同一个关闭流程。关闭后会回到打开详情前的页面，并把键盘焦点还给刚才的操作位置，不会另外写一套容易出错的返回逻辑。

这次没有改探索脚本、热点数据、NPC 对话内容、阅读按钮样式、详情卡片样式，也没有改变任何存档字段和剧情事实。

## 二、给高冰轩：页面配合上需要知道什么

全局现在会在 `.game-main` 上提供当前页面状态：

```text
data-view-state="reading"
data-view-state="exploration"
data-view-state="detail"
data-view-state="inventory"
data-view-state="minigame"
```

你可以直接根据这个状态设计页面：

- `reading`：显示底部对话框；场景可以保留，热点必须表现为不可操作。
- `exploration`：显示场景和热点，阅读框隐藏。
- `detail`：显示物品详情卡片，底下的场景或背包只是背景。
- `inventory`：显示背包覆盖层。
- `minigame`：显示地图小游戏覆盖层。

你负责的是“长什么样”，全局负责的是“现在应该显示哪一个”。请不要在 CSS 或页面按钮里自己修改剧情状态，也不要根据按钮文字猜当前状态。

详情右上角的“×”由你放在卡片内部并完成样式。按钮仍然使用页面约定的关闭入口，让全局统一执行返回。遮罩点击不关闭详情；ESC 已由全局接管。

移动端对话框放在场景下方、选项纵向排列、最大高度和滚动区域，都属于页面布局；全局只会稳定提供 `reading` 状态，不会干涉这些视觉实现。

## 三、给卢正松：探索配合上需要知道什么

探索模块负责判断玩家点的是谁、点的是什么，并把请求交给全局；不要直接隐藏或显示其他模块的页面。

配合方式是：

- 玩家点 NPC：探索模块提供对应的阅读输入，请求全局进入 `reading`。
- 玩家点物品：探索模块把物品 ID 交给统一详情入口，请求全局进入 `detail`。
- 对话读完：探索/对话模块报告真正完成的结果；全局根据最新剧情响应决定回探索还是继续阅读。
- 详情关闭：探索模块不用处理返回，全局会自动回到打开详情前的状态。

探索模块不要自己做以下事情：

- 不要直接修改 `#game-scene`、`.story-panel`、`#detail-root` 的 `hidden`。
- 不要自己维护另一份当前页面状态。
- 不要为了关闭详情修改剧情事实或 `storyCheckpoint`。
- 不要在详情关闭后手动重新创建探索页面。

全局没有改你的热点数据、调查事实、`module.interact()` 或探索事件提交逻辑。你可以在自己的分支上继续完成 NPC/物品分流，然后通过全局提供的入口接入。

## 四、给两位同学的 Agent：代码级交接

### 4.1 本轮实际修改

只修改：

```text
assets/js/core/game-page-controller.js
```

修改一：`createViewCoordinator().render()` 每次渲染时，把 `currentView` 同步到最近的 `.game-main`：

```js
sceneRoot.closest?.(".game-main")?.setAttribute("data-view-state", currentView);
```

目的：页面 CSS 可以稳定使用 `.game-main[data-view-state="..."]`，不用复制页面状态判断。

修改二：在正式游戏页注册 `keydown`，只在当前状态为 `detail` 且按键为 `Escape` 时调用现有的：

```js
viewCoordinator.closeOverlay()
```

并在 `pagehide` 时移除监听，避免重复注册和页面离开后的残留回调。

### 4.2 已有全局接口，不要另造一套

页面状态常量：

```js
VIEW_STATES.READING
VIEW_STATES.EXPLORATION
VIEW_STATES.DETAIL
VIEW_STATES.INVENTORY
VIEW_STATES.MINIGAME
```

覆盖层入口：

```js
viewCoordinator.openOverlay(nextView)
viewCoordinator.closeOverlay()
viewCoordinator.getReturnState()
```

对探索模块公开的详情请求：

```js
host.requestOpenDetail(targetId)
```

页面公开入口：

```js
globalThis.WhiteLamp.gamePage.openDetail(targetId)
globalThis.WhiteLamp.gamePage.closeOverlay()
```

NPC 阅读由控制器传给探索视图的 `openConversation(input, callbacks)` 进入 `reading`；完成和关闭后的去向仍由全局控制器统一安排。

### 4.3 状态规则

- `showBase(reading | exploration)` 会清空覆盖层返回链，切换基础页面。
- `openOverlay(detail | inventory | minigame)` 会记录当前状态和打开前焦点。
- `closeOverlay()` 会回到上一状态并恢复焦点。
- 底层保留显示时，通过 `inert` 和 `is-view-locked` 禁止交互。
- 详情查看只是页面行为，不允许调用 `handleExternalEvent()` 提交调查事实。
- 页面样式、热点分类、NPC Choice 数据均不属于本轮全局改动。

### 4.4 接入时各 Agent 应修改的归属

高冰轩的 Agent：

```text
pages/game.html
assets/css/game.css
```

负责详情“×”、对话框结构、移动端布局和 Choice 视觉；读取全局提供的 `data-view-state`，不要修改全局状态机。

卢正松的 Agent：

```text
assets/js/exploration/**
```

负责识别 NPC/物品、准备阅读或详情请求、提交真实探索结果；调用全局入口，不直接控制其他页面容器。

全局 Agent：

```text
assets/js/core/game-page-controller.js
```

只负责状态切换、覆盖层返回、背景锁定、焦点恢复和统一关闭。

## 五、联调验收

三个人合并后按下面顺序检查：

1. 探索状态点击 NPC，进入阅读；热点看得见或隐藏都可以，但必须点不动。
2. 对话结束后回到探索，原场景仍可继续操作。
3. 探索状态打开详情，底下内容不能被点击。
4. 点击详情关闭按钮和按 ESC，结果完全一致。
5. 关闭详情后回到原探索状态，焦点回到打开详情前的位置。
6. 从背包打开详情时，关闭详情先回背包，不直接跳到探索。
7. 所有页面打开和关闭都不能改变 `facts` 或 `storyCheckpoint`，只有真实调查、对话完成和剧情动作才能提交进度。
