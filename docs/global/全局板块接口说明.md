# 《借灯》全局板块接口说明

> 面向：剧情、探索、背包、拼图、成就、账户、页面与视觉模块成员。  
> 当前版本：V1.1（`state.js`、`storage.js` 与 `navigation.js` 已接入。）

## 先看这一页：你需要做什么

如果你的模块让游戏发生了“需要在刷新或读档后记住”的事情，不要直接改背包、成就、剧情节点或浏览器存储。正式业务模块应把外部结果交给宿主协调器：

```js
const result = await host.dispatchExternalEvent(event);
```

`applyGameEvent()` 只供游戏宿主和全局状态内部登记已确认的应用事件使用；探索、对话、小游戏等业务模块不得直接调用它。外部事件携带的 `resultFactIds` 只是候选事实，由剧情引擎和状态模块校验；剧情推进与校验成功后，检查点、状态事件和正式事实才一起提交。

下面这些事情必须通过事件更新：

- 获得物品、调查对象、首次与人物对话；
- 作出会影响后续内容的选择；
- 改变剧情节点或阶段；
- 完成地图拼图；
- 解锁成就。

打开或关闭背包、临时提示文字、鼠标位置等不需要存进游戏状态。

## 1. 模块边界

| 角色与模块 | 输入 → 输出 | 状态权限 |
| --- | --- | --- |
| 指挥：导航、流程、状态、存档 | 身份、玩家操作、结果事件 → 已提交状态、命令分发、存档 | 导航组装与检查身份；流程统一提交；状态工具生成新状态；存档负责持久化 |
| 大脑：剧情引擎 | 检查点、候选事实、输入 → 剧情提交、命令、展示数据 | 校验任务结果，决定推进与奖励；不直接修改状态或 DOM |
| 手脚：探索、对话、拼图 | 当前命令、只读状态 → 外部结果事件 | 不登记正式事实、不切 Node、不写存档 |
| 展示：剧情视图、背包、成就页 | 已提交状态、展示数据 → 界面与玩家操作 | 只读；操作回交宿主或执行模块 |
| 规则结算：成就规则 | 已确认事实、已有成就 → 待登记解锁事件 | 不直接写状态；宿主调用规则并登记 |
| 身份支持：账户 | 登录/游客选择 → 会话与 `storageScope` | 只管理身份，不管理游戏进度 |

`WhiteLamp.game.update` 与 `gameFlow.replaceState` 保留旧宿主兼容性，仅供宿主内部使用；业务接入使用 `host.dispatchExternalEvent` 或 `WhiteLamp.game.handleExternalEvent`。

禁止以下写法：

```js
gameState.inventory.push("key-a");
gameState.achievements.push("map-restorer");
localStorage.setItem("white-lamp:save:guest:v2", "...");
```

## 2. 与账户模块如何对接

账户模块公开接口是 `window.WhiteLamp.auth`，游戏模块只需要关心它返回的 `storageScope`。

```js
const sessionResult = await window.WhiteLamp.auth.getSession();

if (!sessionResult.ok) {
  // 在页面显示 sessionResult.message，不要继续创建或读取游戏状态。
} else if (sessionResult.data === null) {
  // 没有会话，跳回登录页。
  window.location.replace("authorize/login.html");
} else {
  const { storageScope } = sessionResult.data;
  // 新游戏：createInitialGameState(storageScope)
  // 继续游戏：由后续 storage.js 读取此 storageScope 对应的存档。
}
```

`storageScope` 的唯一合法格式：

| 玩家身份 | `storageScope` | 说明 |
| --- | --- | --- |
| 游客 | `guest` | 所有游客使用同一个游客进度域 |
| 注册账户 | `account:<userId>` | `userId` 是账户模块生成的 UUID |

不要使用 `username` 当存档键；不要读取账户列表、密码摘要或 `sessionStorage`。

主菜单需要按下面顺序加载账户脚本；自己的全局入口脚本放在其后：

```html
<script defer src="../assets/js/authorize/config.js"></script>
<script defer src="../assets/js/authorize/storage.js"></script>
<script defer src="../assets/js/authorize/crypto.js"></script>
<script defer src="../assets/js/authorize/auth-service.js"></script>
<script type="module" src="../assets/js/core/navigation.js"></script>
```

## 3. 当前 `state.js` 的宿主/状态内部接口

文件：`assets/js/core/state.js`

```js
import {
  GAME_EVENTS,
  createInitialGameState,
  applyGameEvent
} from "../core/state.js";
```

### 3.1 创建新游戏

```js
let gameState = createInitialGameState(storageScope);
```

新游戏固定从 `prologue-wake`、`prologue` 开始。传入非法的 `storageScope` 会抛出错误，避免账户存档与游客存档串在一起。

### 3.2 更新状态（仅宿主/状态内部）

```js
// 宿主内部登记已确认事件；对象调查等外部结果不得直接走此入口。
const achievementEvents = getAchievementEvents({ state: gameState });
for (const event of achievementEvents) {
  gameState = applyGameEvent(gameState, event);
}
```

`applyGameEvent()` 不会修改传入的旧对象，而是返回新对象。因此必须写回 `gameState`。它只登记已经由宿主确认的应用事件；业务模块应调用 `host.dispatchExternalEvent()`，不得绕过剧情协调器。错误事件或错误 ID 会抛出错误；宿主应捕获错误并给玩家可理解的提示。

```js
try {
  gameState = applyGameEvent(gameState, event); // 仅宿主/状态内部
} catch (error) {
  console.error("[white-lamp:global] 状态更新失败", error);
  // 例如：showFeedback("操作未完成，请重试。", "error");
}
```

### 3.3 游戏状态结构

以下为主要字段摘录，完整结构由 `createInitialGameState()` 定义；剧情位置以 `storyCheckpoint` 为准。

```js
{
  schemaVersion: 2,
  storageScope: "guest 或 account:<userId>",
  facts: [],
  storyCheckpoint: null,
  processedRequestIds: [],
  processedExternalEventIds: [],
  appliedOnceKeys: [],
  currentNodeId: "prologue-wake",
  stage: "prologue",
  stageProgress: { "prologue-started": true },
  choices: {},
  investigated: [],
  talkedTo: [],
  inventory: ["burned-work-id", "blue-glass-bead"],
  clues: [],
  puzzle: { mapRestored: false },
  achievements: [],
  updatedAt: null
}
```

业务模块可以读取这些字段，但不得删除字段、改字段名或直接修改数组。`updatedAt` 由存档模块在保存成功时写入。

## 4. 事件速查表

所有 `payload` 中的内容 ID 都必须是小写 kebab-case，例如 `key-a`、`prologue-wake`、`map-puzzle`。

| 类别 | 示例 | 交接与登记 |
| --- | --- | --- |
| 外部结果 | `OBJECT_INVESTIGATED`、`NPC_TALKED`、`MAP_PUZZLE_COMPLETED` | 执行模块交给 `dispatchExternalEvent`；先生成候选状态，剧情校验成功后统一提交 |
| 剧情提交 | `STORY_FACT_RECORDED`、`ITEM_ACQUIRED`、`CLUE_RECORDED`、`LOCATION_UNLOCKED` | 引擎在 `commit.events` 中返回，协调器通过 `commitStoryTransaction` 连同检查点登记 |
| 应用内部事件 | `ACHIEVEMENT_UNLOCKED` | 宿主根据成就规则的结果调用 `applyAppEvent`，内部使用 `applyGameEvent` |

背包、调查、对话和成就都会自动去重。因此重复点击、重复发事件或读档后重新展示内容，不会发放重复奖励。

### 4.1 小游戏结果交接示例

业务模块向宿主提交外部结果。以下示例包含剧情命令关联字段；业务模块不得自行调用 `applyGameEvent()`：

```js
await host.dispatchExternalEvent({
  eventId: `evt-${crypto.randomUUID()}`,
  eventType: "MAP_PUZZLE_COMPLETED",
  source: "minigame",
  causedByCommandId: command.commandId,
  resultFactIds: [command.payload.successFactId],
  payload: { puzzleId: command.payload.minigameId }
});
```

剧情模块决定后续节点；业务模块不得直接切入老宅节点。宿主将候选结果交给剧情入口，响应成功后与 checkpoint 一起提交，再登记成就。

同一结果重试时复用原 `eventId`；失败不登记此 ID，已成功结果重复提交不会重复结算。

提交前失败返回 `ok:false`，正式状态不变。提交后的通知或展示失败会明确报错，不回滚进度；流程返回 `ok:true`，并可附带 `warning.errorCode = "FLOW_EFFECT_FAILED"`。正式宿主在成就登记后统一刷新展示，刷新异常同样显示错误。

## 7. 当前 `storage.js` 存档接口

文件位置：`assets/js/core/storage.js`。这是游戏存档模块，不是账户模块的 `assets/js/authorize/storage.js`。

```js
import {
  getSaveKey,
  validateGameState,
  saveGame,
  loadGame,
  hasValidSave,
  deleteSave
} from "../core/storage.js";
```

### 7.1 存档键

存档键由 `storageScope` 和 `SAVE_SCHEMA_VERSION` 自动生成：

```text
white-lamp:save:guest:v2
white-lamp:save:account:<userId>:v2
```

不要手写存档键，也不要用用户名代替 `storageScope`。

### 7.2 保存

```js
const result = saveGame(gameState, storageScope);

if (result.ok) {
  gameState = result.data.state;
  console.log("保存成功", result.data.savedAt);
} else {
  console.error(result.code, result.message);
}
```

保存前会检查：

- 游戏状态字段和 `schemaVersion` 是否正确；
- `gameState.storageScope` 是否与当前会话一致；
- 浏览器是否允许使用 `localStorage`。

只有真正写入成功后才更新 `updatedAt`。失败时不会返回“保存成功”。

### 7.3 读取和继续游戏

```js
const result = loadGame(storageScope);

if (result.ok) {
  gameState = result.data;
} else if (result.code === "SAVE_NOT_FOUND") {
  // 主菜单禁用“继续游戏”，显示“暂无存档”。
} else {
  // 显示 result.message；损坏存档不会被自动删除。
}
```

`loadGame()` 会捕获 JSON 解析错误、版本不一致、缺字段、存储域不一致等情况。

### 7.4 其他函数

```js
hasValidSave(storageScope); // 只有存在且完整合法时才返回 true
deleteSave(storageScope);   // 仅在玩家明确确认删除/覆盖时调用
validateGameState(value);   // 只校验，不读取或写入浏览器
```

所有存档函数都返回 `{ ok: true, ... }` 或 `{ ok: false, code, message }`；页面必须根据 `ok` 显示反馈。

### 7.5 禁止事项

```js
// 禁止：业务模块直接读写游戏存档。
localStorage.setItem("white-lamp:save:guest:v2", "...");

// 禁止：忽略失败结果，继续把坏数据当作正常状态使用。
const state = loadGame(storageScope).data;
```
