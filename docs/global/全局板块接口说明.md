# 《借灯》全局板块接口说明

> 面向：账户、剧情、探索、对话、背包、小游戏、成就和页面模块负责人。
> 当前状态：V1 正式接入完成。
> 当前接口：剧情合同 `1.0`，游戏存档 schema `2`。
> 最后核对：2026-09-06，基于本地 `feature_global`。

## 1. 一句话规则

业务模块只负责展示和报告“玩家做了什么”；`state.js` 统一记录状态，`game-flow.js` 唯一协调剧情推进，`storage.js` 唯一读写游戏存档。

禁止业务模块：

- 直接修改 `gameState` 数组或对象；
- 直接读写游戏存档 `localStorage`；
- 在探索、对话或小游戏事件中指定下一个剧情 Node；
- 在状态尚未提交成功时显示奖励已经到账。

## 2. 当前正式文件与职责

| 文件 | 当前职责 |
| --- | --- |
| `assets/js/core/game-contract.js` | 统一登记事件类型、通知类型、V1 事实和事实生产者 |
| `assets/js/core/state.js` | 创建初始状态；校验并提交外部事件、剧情事务和应用事件；统一去重 |
| `assets/js/core/storage.js` | 按身份保存、读取、校验和删除单个最近存档 |
| `assets/js/core/game-flow.js` | 组织新游戏、读档恢复、剧情操作和外部事件；调用剧情唯一入口 |
| `assets/js/core/navigation.js` | 接入账户、主菜单、正式游戏页、探索/对话、地图小游戏、成就和保存按钮 |
| `assets/js/core/game-ui.js` | 展示已经提交的剧情响应和状态，不决定业务状态 |

正式游戏入口为 `pages/game.html`，正式主菜单为 `pages/menu.html`。`pages/exploration/game.html?demo=1` 是模块演示环境，不能作为正式存档或正式游戏入口。

## 3. 唯一可信进度与兼容字段

剧情进度的唯一可信来源是：

```js
gameState.storyCheckpoint = {
  nodeId: "village-inquiries",
  nodeRevision: 1,
  completedMilestoneIds: [],
  completedNodeIds: [],
  completedStageIds: ["prologue"],
  pendingCommands: []
};
```

| 字段 | 含义 |
| --- | --- |
| `nodeId` | 当前剧情 Node |
| `nodeRevision` | 当前 Node 的语义版本，用于读档兼容检查 |
| `completedMilestoneIds` | 当前 Node 已完成的里程碑 |
| `completedNodeIds` | 本局已完成的 Node |
| `completedStageIds` | 本局已完成的阶段 |
| `pendingCommands` | 尚未完成的探索、对话或小游戏任务摘要 |

`currentNodeId`、`stage`、`stageProgress` 是旧页面仍可能读取的兼容投影，不是第二套进度来源。`state.js` 在每次剧情事务提交时从 `storyCheckpoint` 重新生成它们；`storage.js` 读入早期 schema 2 存档时也会重建，并在完整校验中检查一致性。

任何新模块都应读取 `storyCheckpoint`。不要写入兼容字段，也不要用 `stage` 决定剧情推进。

当前 V1 阶段投影规则：

| Node | `stage` |
| --- | --- |
| `prologue-*` | `prologue` |
| `village-*` | `village` |
| `old-house-*`、`week-one-end` | `old-house` |

`stageProgress` 只包含三个阶段的 `*-started` 和 `*-completed` 布尔投影。例如到达村口时，`prologue-completed` 和 `village-started` 为 `true`。

## 4. 状态结构

新游戏由以下函数创建：

```js
const gameState = createInitialGameState(storageScope);
```

当前 schema 2 的持久状态主要包含：

```js
{
  schemaVersion: 2,
  storageScope: "guest", // 或 account:<UUID>
  updatedAt: null,
  facts: [],
  storyCheckpoint: null,
  processedRequestIds: [],
  processedExternalEventIds: [],
  appliedOnceKeys: [],

  currentNodeId: "prologue-wake", // 兼容投影
  stage: "prologue",              // 兼容投影
  stageProgress: {                 // 兼容投影
    "prologue-started": true,
    "prologue-completed": false,
    "village-started": false,
    "village-completed": false,
    "old-house-started": false,
    "old-house-completed": false
  },

  investigated: [],
  explorationState: {},
  talkedTo: [],
  conversationState: {},
  inventory: ["burned-work-id", "blue-glass-bead"],
  clues: [],
  unlockedLocations: [],
  puzzle: { mapRestored: false },
  minigameState: {},
  choices: {},
  achievements: []
}
```

业务模块可以读取自己所需的已提交投影，但不得直接修改。小游戏 V1 只承诺保存“是否完成”；拼图中途退出或读档后重新开始本局拼图，`minigameState` 暂不保存棋盘布局。

## 5. 三类更新入口

### 5.1 外部模块结果

探索、对话和小游戏通过 `gameFlow.handleExternalEvent(event)` 上报结果。当前成功事件：

| 来源 | 允许的成功事件 |
| --- | --- |
| `exploration` | `OBJECT_INVESTIGATED` |
| `conversation` | `NPC_TALK_PROGRESS`、`NPC_TALKED` |
| `minigame` | `MAP_PUZZLE_COMPLETED` |

事件必须包含：

```js
{
  eventId: "本次结果的唯一 ID",
  eventType: "OBJECT_INVESTIGATED",
  source: "exploration",
  causedByCommandId: "剧情原命令 ID",
  resultFactIds: ["burned-work-id-investigated"],
  payload: { objectId: "burned-work-id" }
}
```

`state.js` 会检查事件来源、对应命令、事实生产者和重复 ID。事件只报告已经发生的结果，不携带 `nextNodeId`。

取消或失败使用 `EXTERNAL_INTERACTION_CANCELLED` / `EXTERNAL_INTERACTION_FAILED`，`resultFactIds` 必须为空；失败载荷还必须包含 `errorCode`。

### 5.2 剧情事务

只有 `game-flow.js` 调用：

```js
window.WhiteLamp.story.enterStory(request);
```

协调顺序固定为：

1. 外部事件先由 `state.js` 校验并记录事实；
2. `game-flow.js` 把最新事实和检查点交给剧情；
3. 剧情返回 `commit`、`commands`、`notifications` 和 `presentation`；
4. `commitStoryTransaction()` 原子提交检查点及剧情奖励事件；
5. 提交成功后才发布完整命令、通知和页面展示。

探索、对话和小游戏不得直接调用 `enterStory()`，也不得直接修改检查点。

### 5.3 应用内部事件

不经过剧情的应用事件由 `gameFlow.applyAppEvent(event)` 提交。V1 当前用于 `GAME_STARTED` 和 `ACHIEVEMENT_UNLOCKED`。

剧情发放物品、记录线索和开放地点使用剧情事务中的 `ITEM_ACQUIRED`、`CLUE_RECORDED`、`LOCATION_UNLOCKED` 等事件，外部模块不能绕过剧情自行发奖。

## 6. 探索、对话和小游戏宿主接口

正式页面在账户会话与存档恢复完成后创建宿主：

```js
const host = {
  getContext() {
    return {
      storageScope,
      state: gameFlow.getState(),
      commands: activeCommands
    };
  },
  subscribe(listener) {
    // 返回取消订阅函数
  },
  dispatchExternalEvent(event) {
    return gameFlow.handleExternalEvent(event);
  }
};
```

`storyCheckpoint.pendingCommands` 只保存可恢复的任务摘要。业务模块执行任务时还需要剧情响应中带 `payload/goals` 的完整 `commands`。`game-flow.js` 必须先通过 `onCommandsChange` 发布完整命令，再通知状态订阅者刷新。

### 探索与对话

`createInteractionModule(host)` 组合：

- `exploration`：物体热点、调查和背包回读；
- `conversation`：NPC 对话、进展和确认；
- `integration`：按动作归属路由，不保存业务状态。

同一页面显示它们，不代表它们拥有同一事实来源。调查事实由 `exploration` 产生，对话事实由 `conversation` 产生。

### 地图小游戏

`map-puzzle-adapter.js` 接收完整 `REQUEST_MINIGAME` 命令，运行拼图，成功后发出：

```js
{
  eventType: "MAP_PUZZLE_COMPLETED",
  source: "minigame",
  causedByCommandId: "原命令 ID",
  resultFactIds: ["map-puzzle-completed"],
  payload: { puzzleId: "map-puzzle" }
}
```

小游戏不发完整地图、不开放老宅、不解锁成就、不决定下一 Node。剧情决定完整地图和老宅奖励；成就规则根据已提交事实生成成就事件；玩家再执行 `go-old-house` 才推进老宅。

## 7. 账户与存档接口

账户模块只提供当前身份：

```js
const sessionResult = await window.WhiteLamp.auth.getSession();
const { storageScope } = sessionResult.data;
```

合法存储域只有 `guest` 和 `account:<用户 UUID>`。不要用用户名作为存档键。账户存储文件是 `assets/js/authorize/storage.js`；游戏存档文件是 `assets/js/core/storage.js`，两者不能混用。

游戏存档公开接口：

```js
getSaveKey(storageScope);
validateGameState(value);
saveGame(gameState, storageScope);
loadGame(storageScope);
hasValidSave(storageScope);
deleteSave(storageScope);
```

当前存档键示例：

```text
white-lamp:save:guest:v2
white-lamp:save:account:<用户 UUID>:v2
```

所有操作返回 `{ ok: true, data }` 或 `{ ok: false, code, message }`。页面必须区分：

| code | 页面处理 |
| --- | --- |
| `SAVE_NOT_FOUND` | 明确显示暂无存档；可以展示初始锁定内容 |
| `SAVE_INVALID` | 显示存档损坏；保留原数据；不能冒充新游戏状态 |
| `SAVE_VERSION_UNSUPPORTED` | 显示版本不兼容；保留旧档 |
| `SAVE_SCOPE_MISMATCH` | 停止加载，提示当前身份不匹配 |
| `STORAGE_UNAVAILABLE` | 显示浏览器存储不可用及返回路径 |

旧 schema 1 存档不会自动迁移，也不会自动删除。schema 2 早期存档如果只有兼容阶段字段落后，读取时会从合法 `storyCheckpoint` 重建投影；剧情 Node 或 revision 是否有效，仍由剧情模块在 `resume` 时继续校验。

## 8. 主菜单和正式游戏页

`navigation.js` 当前已经负责：

- 读取账户会话；
- 根据存档结果控制“继续游戏”；
- 启动新游戏或恢复游戏；
- 建立 `gameFlow` 和业务宿主；
- 挂载探索/对话与地图适配器；
- 提交地图相关成就；
- 保存当前完整状态；
- 返回菜单及页面卸载清理。

正式游戏页必须包含：`#game-scene`、`#exploration-actions`、`#inventory-panel`、`#minigame-root`、`#game-story`、`#game-actions` 和 `#feedback`。

页面只显示已经提交成功的状态。失败时必须显示玩家可理解的信息，并在控制台保留模块名和技术原因。

## 9. 接入检查清单

- [ ] 账户身份与存档恢复完成后，才挂载业务模块。
- [ ] 读取 `storyCheckpoint` 判断剧情进度，不读取兼容字段作业务判断。
- [ ] 使用当前合同事件，并带 `eventId/source/causedByCommandId/resultFactIds/payload`。
- [ ] 事件引用协调器交付的原命令 ID，不自行构造下一 Node。
- [ ] 状态更新后读取全局返回的新状态，不直接修改旧对象。
- [ ] 只有 `storage.js` 读写游戏存档。
- [ ] 失败结果不会被页面显示成成功，也不会静默清空原数据。
- [ ] 新增 Node、事实、事件、小游戏或存档字段时，同步更新合同、校验和迁移说明。

## 10. V1 已知边界

- 单个最近存档，不支持多档位、后端、云同步或跨设备同步。
- 手动保存；返回菜单、刷新和关闭页面不会自动保存最新操作。
- 拼图只保存完成结果，不保存进行中的棋盘布局；恢复后重新开始当前拼图。
- V1 已按剧情变更取消“相信/怀疑小 X”选项。
- “追问过去”对白可显示，但可选记忆事实的持久化仍受剧情命令能力限制，由剧情与探索后续协同处理。
- 新增第二小游戏、证据删改、多结局和后续剧情时，需要扩展事实表、状态结构及存档兼容规则。
