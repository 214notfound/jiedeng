# 《借灯》V2 界面状态切换约定

> 本文是 V2 正式 `pages/game.html` 的界面交接约定。它只规定“当前屏幕显示什么、玩家下一步能做什么、操作结束后回到哪里”，不决定剧情 Node，也不替代剧情、探索或小游戏模块的业务规则。

## 1. 全局规则

1. 游戏同一时刻只能处于一个主界面状态：`reading`、`exploration`、`detail`、`inventory`、`minigame`。
2. 只有 `game-flow.js` 负责根据剧情响应切换主状态；业务模块只能提出打开、关闭或提交结果的请求。
3. 只有 `state.js` 提交事实和剧情状态；探索、对话、详情、背包和小游戏不能自行修改 `storyCheckpoint` 或决定下一个剧情 Node。
4. `detail`、`inventory`、`minigame` 属于覆盖层。覆盖层打开时，场景热点、人物和其他背景按钮必须锁定，不能发生穿透点击。
5. 页面只显示玩家能理解的故事、结果和提示；`Node`、`eventType`、`commandId`、事实 ID、错误码、函数名和调用栈只写入开发者控制台。
6. 关闭覆盖层后，回到打开前的状态和焦点；不能默认跳回新状态，也不能因为关闭而提交事实。
7. 缺少必要字段时直接返回错误并记录缺少的字段，不在调用处猜默认值。

## 2. 状态与正式页面容器

以下是当前 `pages/game.html` 已存在或可复用的容器。带“待确认”的项目必须由高冰轩确认真实 ID、挂载方式和显示/隐藏规则后才能作为正式接口使用。

| 状态 | 用人话解释 | 当前可见容器 | 正式容器确认人 |
|---|---|---|---|
| `reading` | 看旁白、剧情或人物对话 | `#game-story`、`#game-actions`；独立阅读层 ID 待确认 | 高冰轩 |
| `exploration` | 在场景中点击物体或人物 | `#game-scene`、`#exploration-actions` | 高冰轩 |
| `detail` | 查看某个线索的详细说明 | 详情容器 ID 待确认 | 高冰轩 |
| `inventory` | 查看背包和已获得线索 | `#inventory-panel`（是否作为覆盖层显示待确认） | 高冰轩 |
| `minigame` | 玩地图拼图 | `#minigame-root` | 高冰轩 |

容器必须满足：显示状态下可操作，隐藏状态下不占位、不接收点击；切换后不能同时显示两个主状态。

## 3. 五种状态切换表

| 状态 | 进入条件 | 背景锁定 | 完成后 | 取消后 | 失败后 | 返回给 `game-flow` 的结果 |
|---|---|---|---|---|---|---|
| `reading` | 剧情响应为 `ready` 且有 `presentation`；或玩家选择一个对话命令后打开 NPC 对话 | 是。阅读时不能点场景热点 | 阅读组件只在最后一段结束时回调一次；由剧情响应决定进入 `exploration`、继续等待外部任务或结束展示 | 回到打开阅读前的状态；不推进剧情、不产生事实 | 保留当前内容，显示可理解的提示；不改变 `storyCheckpoint` | `reading-complete`、`reading-cancelled` 或 `reading-failed`，并附必要的来源信息 |
| `exploration` | 剧情响应要求调查/对话，或 `waiting-external` 中包含 `REQUEST_EXPLORATION` / `REQUEST_CONVERSATION` 命令 | 否。只允许当前场景中的有效热点和人物入口接收点击 | 点击结果提交给 `game-flow → state`；只有提交成功后才刷新已调查/已完成显示，并按最新剧情响应切换 | 保持 `exploration`；未提交事实 | 保持 `exploration`，显示失败原因；热点不能伪装成已完成 | 探索事件或对话请求；模块不携带下一个 Node |
| `detail` | 玩家从探索或背包中打开一个已获得的线索 | 是。禁止点击背后场景 | 关闭详情并回到打开前的状态；重复查看不产生新事实或奖励 | 同完成：回到打开前的状态 | 显示“无法读取详情”等提示；不清空背包、不新增事实 | `detail-closed` 或 `detail-failed` |
| `inventory` | 玩家点击背包入口 | 是。禁止点击背后场景 | 关闭背包并回到打开前的状态；只读显示已提交内容 | 回到打开前的状态 | 保留当前已知内容，显示读取失败提示；不能显示伪造的初始列表 | `inventory-closed` 或 `inventory-failed` |
| `minigame` | `waiting-external` 中包含 `REQUEST_MINIGAME`，且玩家选择打开地图拼图 | 是。禁止点击场景和其他界面 | 仅提交 `MAP_PUZZLE_COMPLETED` 事实；成功后由最新剧情响应决定下一状态；只保存“是否完成” | 回到 `exploration`；不能产生完成事实 | 留在拼图或按约定返回 `exploration`，显示失败原因；不能提交完成事实 | `MAP_PUZZLE_COMPLETED`、`minigame-cancelled` 或 `minigame-failed` |

## 4. 剧情响应状态到界面的映射

界面不能根据按钮文字猜剧情进度，必须读取最新剧情响应的 `status`、`presentation` 和完整 `commands`。

| 剧情响应 | 界面处理 |
|---|---|
| `ready` | 必须有 `presentation`，进入 `reading`，显示旁白、系统文字或人物对白。没有新的外部命令时，玩家只能继续阅读。 |
| `waiting-external` + `REQUEST_EXPLORATION` 或 `REQUEST_CONVERSATION` | 进入或保持 `exploration`，等待玩家点击物体或人物；命令由探索/对话模块消费。 |
| `waiting-external` + `REQUEST_MINIGAME` | 保持剧情等待；页面显示地图入口或进入 `minigame` 的按钮。玩家确认打开后才显示拼图覆盖层。 |
| `waiting-external` 同时包含多个村民对话命令 | 仍保持 `exploration`，显示多个可选择的村民入口，由玩家选择一个后才进入 `reading`；不得自动执行第一个命令，也不得同时打开多个阅读窗口。取消对话后回到 `exploration`。 |
| `ended` | 进入结束展示（使用 `reading` 的结束呈现或专用结束容器，具体 ID 待确认），显示阶段结束提示；`commands` 必须为空，不再接受剧情推进操作。 |
| `error` | 保留最近一个有效界面状态，显示玩家能理解的错误提示；不得清空状态、伪装成新游戏或推进剧情。 |

## 5. 打开、关闭和返回规则

### 5.1 打开覆盖层

业务模块提出“打开详情”“打开背包”或“打开地图”的请求，统一交给页面宿主/`game-flow`。请求至少包含：

```text
请求类型：detail | inventory | minigame
打开前状态：reading | exploration
目标 ID：线索 ID、地图命令 ID 等（由对应模块提供）
```

协调器记录 `returnState` 和必要的焦点元素，显示目标覆盖层并锁定背景。业务模块不能直接修改其他容器的 `hidden` 属性来切换主状态。

### 5.2 关闭覆盖层

关闭时销毁或清理当前覆盖层的临时监听，恢复 `returnState` 对应容器和焦点。关闭本身不提交剧情事实、不改变 `storyCheckpoint`。

### 5.3 操作结果

- 成功：模块把真实事件交给 `game-flow.handleExternalEvent`；只有返回 `ok: true` 后才刷新完成状态。
- 取消：返回约定的上一个界面，不产生事实。
- 失败：返回 `{ok: false, ...}` 或等价失败结果，保留原状态和已有数据。

## 6. 存档恢复规则

恢复游戏时不读取旧页面 DOM、旧动画位置或拼图中途布局来猜当前界面。统一流程如下：

1. `storage.js` 读取并验证存档。
2. `game-flow.js` 根据存档中的 `storyCheckpoint` 和状态调用剧情恢复入口。
3. 以恢复得到的最新 `status`、`presentation` 和完整 `commands` 重建界面。
4. 按第 4 节映射到唯一一个主状态，并重新挂载需要的模块。

恢复映射：

```text
ready + presentation                         → reading
waiting-external + 调查/对话命令             → exploration
waiting-external + 地图命令                  → exploration（显示地图入口）或玩家确认后 minigame
ended                                        → 结束展示
恢复失败（无档/坏档/版本不兼容/存储不可用）   → 保留原数据，显示对应提示，不伪装成新游戏
```

恢复必须保留：

- 最新 `storyCheckpoint`；
- 已提交的 `facts`；
- 完整外部 `commands` 及其 `payload`、`goals` 等执行所需字段；
- 玩家可以返回的路径和可理解的错误反馈。

拼图只恢复“是否已经完成”，不恢复拼图中途的摆放布局。

## 7. 交接确认清单

### 高冰轩确认

- [ ] 五种状态的真实容器 ID 和挂载点。
- [ ] 每个容器的显示/隐藏方式；隐藏时不占位、不接收点击。
- [ ] 覆盖层锁定背景、关闭后恢复焦点的实现方式。
- [ ] `ended` 使用阅读结束呈现还是独立结束容器。

### 于知让确认

- [ ] `ready`、`waiting-external`、`ended` 各提供至少一个真实剧情响应样例。
- [ ] 阅读末尾只回调一次；“继续阅读”不会被误当作剧情 action。
- [ ] 对话完成、取消、失败不会绕过剧情 action 或提前推进 Node。

### 卢正松确认

- [ ] 调查、人物、详情、背包、地图的打开请求和返回结果字段。
- [ ] 多个村民命令时由玩家选择，不自动消费其他命令。
- [ ] 调查和地图完成只有在状态提交成功后才显示完成。

### 罗晨菲确认

- [ ] 状态切换统一经过 `game-flow`，没有业务模块自行切换 Node。
- [ ] 页面订阅能收到最新状态和完整命令；状态提交成功后再刷新视图。
- [ ] 新游戏、继续游戏、无档、坏档、版本不兼容、存储不可用均能区分。

## 8. 最小验收路径

至少在正式 `pages/game.html` 验证以下路径各一次：

1. `ready → reading`：逐段阅读，连续点击不会重复提交。
2. `waiting-external → exploration`：点击一个物体，成功、失败、连续点击各一次。
3. 探索中打开详情，关闭后原热点仍可点击，背景没有穿透点击。
4. 同时出现两个村民命令时仍停留探索，玩家选择其中一个后进入阅读。
5. 打开地图后取消回探索；完成后提交地图事实并显示最新剧情响应。
6. 阅读中保存、调查后保存、地图完成后保存；继续游戏后按最新响应重建正确界面。
7. 无档、坏档、版本不兼容和存储不可用分别显示不同的玩家提示，均不伪装成新游戏。

每次测试记录：入口、预期页面、预期事件/事实、预期存档、实际结果、问题归属和复测结果。
