# 《借灯》项目需求文档 V2

**开发入口：先看 [V2开发执行路线.md](./V2开发执行路线.md)，再把本文件当作详细规格和验收依据。**

配套开发依赖、并行工作线和联调节点见 [V2开发流程图.md](./V2开发流程图.md)。

## 一、版本目标与边界

V2 聚焦游戏内交互页面重构：将剧情阅读、场景探索、线索详情、背包和小游戏拆成互斥的界面状态；剧情与人物对话在独立阅读界面逐段呈现；探索改为直接点击场景中的发光热点。完成后，玩家应能在新界面中连续游玩祠堂、村口、陈家老宅三个阶段，完成调查、对话、地图拼图、奖励结算、保存和继续游戏。V1 的剧情事实、检查点、事件合同和存档结构继续作为业务基础。

V2 不新增剧情阶段、小游戏、证据组合、多结局、配音、人物自由移动、自动寻路。拼图只保存是否完成，不恢复中途布局。

V2 继续**以** **`storyCheckpoint` 作为唯一剧情进度来源**；`currentNodeId`、`stage`、`stageProgress` 只保留为由检查点生成的兼容投影。新代码不得写入或读取这些兼容字段来决定剧情推进，避免全局、剧情和探索使用不同进度。

共同验收范围： 
1. 1280px、390px 指浏览器内容区域宽度,页面不能横向溢出，文字、按钮和场景关键物体不能被遮住(此项由高冰轩负责页面验收，杨梦确认场景图裁切，卢正松确认发光点仍落在正确物体上)。V2 核心操作只要求鼠标点击。

2. 打开线索详情、背包或小游戏窗口时，玩家不能误点窗口后面场景里的发光物体或人物。关闭窗口后，场景才恢复点击。

3. 形成玩家点击后的可见反馈。“可见反馈”只指玩家看得懂并能据此行动的文字，例如“没有找到可继续的存档”“缺少开门所需的旧钥匙”“保存失败，请重试”。`Node`、`eventType`、`commandId`、事实 ID、错误码、函数名和调用栈只允许写入开发者控制台，不能出现在正式页面。玩家提示由触发问题的模块提供含义（高冰轩负责显示位置，罗晨菲负责在正式页面阻止内部数据直接显示。）

## 二、协作开发与联调规则

1. **先对接口再写实现。** 任务开始前，提供方先在对应交接文档中给出真实输入、输出和失败结果；使用方确认字段足够后再接入。缺字段必须退回提供方补齐，不能在调用处自行猜测。
2. **每个接口必须由两方共同跑通。** 提供方先给一份真实输入；使用方在正式 `game.html` 触发它；双方分别检查自己负责的结果。至少验证一次成功、一次取消或失败、一次连续点击。demo 页面和临时假数据只能做模块内部检查。
3. **按调用链联调。** 页面层负责触发和展示，业务模块负责生成内容或外部事件，`game-flow` 负责协调，`state` 负责提交，`storage` 负责保存。任何一层不得越过下一层直接修改其所属数据。
4. **问题按归属回退（这个重点看）。** 页面结构、焦点和响应式问题回到高冰轩；剧情文本、Node、动作含义回到于知让；热点、调查、对话、背包和成就规则回到卢正松；场景构图和素材回到杨梦；状态、存档、事件校验和接线回到罗晨菲。报告问题的人提供复现步骤和预期结果，修复人完成修改后双方复测。


## 三、罗晨菲｜全局、状态与正式集成

文件边界：负责 `assets/js/core/navigation.js`、`game-flow.js`、必要的全局状态接口及正式组装；不编写剧情内容、热点数据、对话内容、拼图规则和场景美术。

### G1 界面状态协调

- **用人话解释：** 写一个"屏幕模式总开关"。游戏同一时间只能处于五种模式之一——看剧情、逛场景、看线索详情、看背包、玩拼图。任何模块想开窗口、关窗口、切模式都必须走这个开关，不能自己乱切；弹窗一打开，背后的场景就锁住点不动。

- **输入：** 剧情响应的 `status/presentation/commands`；探索、对话、详情、背包和小游戏的打开/结束请求；《界面状态切换约定》。
- **处理：** 定义 `reading/exploration/detail/inventory/minigame` 五种状态；规定进入、返回、取消和失败后的状态；同一时刻只允许一个主状态；覆盖层打开时锁定背景操作；不根据按钮文案猜测剧情进度。
- **输出：** 页面可消费的当前界面状态，以及统一的打开、关闭和切换入口。
- **交付物：** 状态枚举、切换函数、状态到页面容器的映射、非法切换反馈。
- **依赖与配合：**
    - 高冰轩先提交容器 ID 与状态显示表，罗晨菲逐项把 `reading/exploration/detail/inventory/minigame` 映射到这些 ID；
    - 于知让提交“剧情 action 完成后进入阅读/等待”的响应样例，卢正松提交“点击物体、点击人物、打开详情、打开地图”的请求样例。
    - 四人在正式页面逐项点击，检查只显示一个主状态、打开详情/地图后场景点击无效、关闭后回到原状态；页面缺容器归高冰轩，状态跳转错误归罗晨菲。
    - **【对接必要性检查】必要对接：** 高冰轩的容器 ID 与状态显示表（状态必须映射到真实容器，没它只能猜 ID）、四人正式页面逐项验收（这就是本卡的验收本身）。**建议精简（待你定）：** 于知让、卢正松的样例只是用来校验进入/退出分支，状态枚举和切换函数骨架可以先写，不必等两份样例都到齐才开工。

### G2 正式宿主与业务模块接线

- **用人话解释：** 把大家各自写好的模块真正装进正式 `game.html` 并接上"总线路"：规定开机顺序（存档恢复完再挂载模块）、模块产生的事件往哪转、状态提交成功后谁更新界面、页面关闭时清理监听。最终让剧情、探索、对话、背包、地图共用同一份状态和剧情指令，而不是各玩各的。

- **输入：** V1 `gameFlow`、探索宿主接口、阅读组件接口、地图 adapter、已提交状态和完整剧情命令。
- **处理：** 保证账户和存档恢复后再挂载模块；先发布完整命令，再通知订阅者；将探索/对话事件交给协调器；状态提交成功后更新界面；页面卸载时释放订阅和视图。
- **输出：** 剧情、探索、对话、背包、地图在正式 `game.html` 中共用同一状态与命令来源。
- **交付物：** 正式 host、模块挂载与卸载代码、外部事件转发、错误路由。
- **依赖与配合：** 罗晨菲先提供正式 host 的函数入口和返回结构；卢正松在正式 `game.html` 点击一个物体、一个人物和地图入口，记录事件输入与返回状态；高冰轩检查模块挂载后只生成一份 DOM、卸载后节点和订阅都清理；于知让在剧情回归中确认每次推进都经过 `enterStory()`。四人共同复现“打开地图—取消—再次打开—完成”，分别核对事件、容器、Node 推进和状态提交。
    - **【对接必要性检查】必要对接：** 罗晨菲先出 host 函数入口与返回结构、卢正松做三类点击验证事件转发、高冰轩验证只生成一份 DOM 且卸载后清理干净。**建议精简（待你定）：** 于知让“确认每次推进都经过 `enterStory()`”与 S2/S3 的剧情回归重复，建议并入 S3 统一验证；“打开地图—取消—再次打开—完成”这一场景罗、卢、高三人即可覆盖，于知让不必到场。

### G3 保存与恢复兼容

- **用人话解释：** 管存档的读写兼容。存档结构沿用 V1 不动；刷新页面或点"继续游戏"后，靠剧情检查点把界面重建回正确位置。专门处理四种异常——没存档、存档损坏、版本不兼容、浏览器存不了，失败就老实报错，不许伪造空状态假装新游戏；拼图只存"完没完成"，不存摆到一半的布局。

- **输入：** 当前 `gameState/storyCheckpoint`、五种界面状态、V1 schema 2 存档。
- **处理：** 保持存档业务结构不变；恢复后以剧情返回的展示和命令重建界面；分别处理无存档、坏档、版本不兼容和存储不可用；不保存临时 DOM、动画位置及拼图中间布局。
- **输出：** 新游戏和继续游戏进入正确节点、场景及待办任务；失败时不伪造空状态。
- **交付物：** 恢复入口适配、错误显示接线、保存/恢复检查记录。
- **依赖与配合：** 于知让写出一个阅读中保存和一个等待对话命令保存的具体检查点；卢正松写出调查后保存、地图完成后保存的状态前后对照；罗晨菲逐个调用 `saveGame/loadGame/resumeGame`，记录返回代码和恢复后的 `storyCheckpoint`；高冰轩在页面刷新后检查只显示对应阅读、探索或地图区域。每个用例由提出者确认事实、检查点和页面均一致。
    - **【对接必要性检查】必要对接：** 于知让写两个检查点样例、卢正松写两份状态前后对照（这是存档测试用例的事实来源，模块负责人自己造不出来）。**建议精简（待你定）：** 高冰轩“刷新后只显示对应区域”与 G4 全链路回归里的页面检查重复，可并入 G4 统一做；本卡阶段罗晨菲用控制台和状态断言自查即可。

### G4 集成验收与问题归属

- **用人话解释：** 当集成测试的主持人兼书记员。把所有人的交付物拼成候选版本，照着完整玩家路径从头玩到尾；每个 bug 记下"怎么点出来的、应该怎样、实际怎样、归谁修"，修完后叫报告人沿同一条点击路径复测，没问题才关闭。

- **输入：** 各负责人已通过独立验证的交付物、三份交接约定、完整 V1 玩家路径。
- **处理：** 组装候选版本；记录复现步骤、预期、实际结果和所属模块；执行跨模块回归；协调修复后的复测。
- **输出：** 可从祠堂连续玩到 `week-one-end` 的正式版本，以及有明确负责人的问题清单。
- **交付物：** 联调记录、阻断问题清单、完整流程验收结果。
- **依赖与配合：** 罗晨菲用一份清单记录“操作入口—预期页面—预期事实—预期保存结果—实际结果”；于知让复核剧情顺序和事实，卢正松复核热点/对话/背包/成就，高冰轩复核页面/阅读/响应式，杨梦复核图片与裁切。每条问题必须带复现点击路径和截图或文字结果，修复后由报告人沿同一路径复测并关闭。
    - **【对接必要性检查】** 本卡本质就是五人联合验收，每人复核各自领域（剧情、交互、页面、美术）就是任务本身，全部为必要对接，无建议删除项。

### G5 玩家反馈与内部信息隔离

- **用人话解释：** 当正式页面的"脱敏检查员"。把所有会露给玩家看的文字清点一遍：Node ID、事件名、命令 ID、错误码、函数名、调用栈这类程序员才懂的内部信息一律不许上页面（只许进控制台），换成"缺少开门所需的旧钥匙"这种玩家看得懂的中文，并定好六类标准提示；正式网址下不许看到任何调试按钮和调试数据。

- **输入：** V1 正式页面中的阶段/节点标签、流程日志、命令卡、事件通知、存档错误和各模块异常文本。
- **处理：** 清点所有会进入页面的字符串；删除 Node ID、事件名、命令 ID、事实 ID、错误码、函数名、内部时间戳和调用栈；为“没有存档、存档损坏、版本不兼容、存储不可用、操作失败、保存成功”分别定义玩家能理解的中文提示；技术详情只写控制台；正式页面不能通过默认 URL 看到联调按钮或调试数据。
- **输出：** 玩家只看到剧情内容、调查结果和下一步可执行提示，无法看到代码内部进度定义。
- **交付物：** 玩家反馈文字清单、正式页面信息暴露检查清单、V1 遗留暴露项修复记录。
- **依赖与配合：** 罗晨菲先列出正式页面所有反馈来源和预期文案；高冰轩删除节点标签、流程日志和命令 ID 显示，并把错误放到统一反馈区；于知让确认剧情文本不被技术字段替代；卢正松确认调查/对话/成就失败只显示玩家提示；杨梦检查反馈文字不遮挡场景。罗晨菲在正式 URL、无 `debug=1` 条件下搜索页面文本并逐条确认没有内部字段，发现问题退回实际显示方修复。
    - **【对接必要性检查】必要对接：** 高冰轩删除页面内部字段并建统一反馈区（DOM 归他）、罗晨菲在正式 URL 最终逐条验收。**建议精简（待你定）：** ①于知让“确认剧情文本不被技术字段替代”可提前到 S1 交样例时自查保证；②卢正松确认调查/对话/成就失败提示，并入 E2/E5 模块自测；③杨梦查“反馈文字不遮挡场景”并入 U4/A3 的三视口检查。本卡最终只做跨模块抽检即可，避免同一件事三处重复拉人。

## 四、高冰轩｜游戏页面与统一阅读组件

文件边界：负责 `pages/game.html`、游戏页样式及统一阅读组件；继续维护地图小游戏在新页面中的容器接入；不修改 `navigation.js`、剧情推进和探索事件规则。

### U1 游戏页结构重构

- **用人话解释：** 把 `game.html` 重搭成一个"分层蛋糕架"：最底层是场景图，往上依次是剧情/对话阅读层、详情层、背包层、小游戏层，再加一块固定不动的导航和提示区。每层给好固定挂载点（容器 ID），被隐藏的层不占空间也不接收点击，之后各业务模块直接往对应挂载点里填内容就行。

- **输入：** 《界面状态切换约定》、五种状态所需内容、现有正式页面挂载点。
- **处理：** 将页面拆成背景场景层、剧情/对话阅读层、详情层、背包层、小游戏层和固定导航反馈区；为每个区域提供稳定挂载点；移除正式界面的节点 ID、命令 ID 和事件日志；隐藏区域不得占位或接受输入。
- **输出：** 可由全局协调器切换、业务模块挂载的页面结构。
- **交付物：** `pages/game.html`、挂载点清单、对应 CSS 结构。
- **依赖与配合：** 高冰轩提交容器 ID 清单及每个容器的显示/隐藏规则；罗晨菲逐项对照状态切换入口；卢正松确认场景、热点、详情、背包和地图各需要哪个容器。三人在同一正式页面检查打开与关闭后 DOM 不重复，地图 adapter 只挂载到 `#minigame-root`，不另建游戏页。

### U2 统一阅读组件

- **输入：** 于知让提供的真实剧情样例、卢正松提供的真实 NPC 对话样例及两者的结束回调。
- **处理：** 按顺序一次展示一个文本块；区分旁白、系统文字和人物对白；显示说话人及合法操作；继续按钮只推进阅读索引，读到末尾才调用业务方回调；阅读时禁止点击阅读框后面场景里的发光物体和人物；异步提交期间防止重复点击。
- **输出：** 剧情与 NPC 对话都能使用、但不替业务模块提交事实的阅读视图。
- **交付物：** 阅读组件、输入数据说明、打开/更新/关闭 API、错误与忙碌状态。
- **依赖与配合：** 于知让提供一段带旁白、对白和 action 的真实数据，高冰轩按字段渲染并点击到末尾，确认只在末尾回调；卢正松提供一段真实 NPC 对话并确认完成回调携带 `conversationId/npcId`；罗晨菲检查回调进入统一协调器后页面才切换。缺字段时记录字段名、样例和所属负责人，组件不自行填默认剧情。

### U3 覆盖层、交互锁与返回

- **输入：** 详情、背包、小游戏的打开请求及打开前界面状态。
- **处理：** 控制层级、焦点和关闭按钮；打开时记录返回目标并禁止背景点击；关闭详情/背包时恢复原界面及焦点；对话和小游戏完成后交由全局状态决定去向；错误时保留安全返回入口。
- **输出：** 不重叠、不穿透、可点击关闭的覆盖层体验。
- **交付物：** 覆盖层组件、焦点恢复、背景锁定和返回处理。
- **依赖与配合：** 高冰轩先列出详情、背包、小游戏的层级和关闭按钮；卢正松点击一个线索、切换一次背包分类、打开一次地图，检查背景物体不能被点击；罗晨菲检查打开前状态被记录、取消/失败/完成后的目标状态来自最新响应。三人共同做一次“详情打开—关闭—原热点仍可点”和“地图取消—返回探索”。

### U4 响应式与正式页面可读性

- **输入：** 杨梦三张场景图、热点坐标、阅读与覆盖层内容。
