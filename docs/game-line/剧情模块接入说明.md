# 剧情模块接入说明

## 1. 当前交付

剧情模块已实现 V1 三阶段、11 个运行 Node、30 个事实、数据预检和统一入口。本轮不包含 `game.html` 展示层，也不代替状态、存档、探索、对话、小游戏或成就模块。

V1 不实现旧需求中的“相信/怀疑小 X”选项；这是主动取消的需求，不是遗漏。引擎仍支持未来数据声明 `choice` 和 `CHOICE_MADE`。

## 2. 浏览器加载顺序

全局页面必须按以下顺序加载脚本：

```html
<script src="../assets/js/game-line/data/story-registry.js"></script>
<script src="../assets/js/game-line/data/prologue.js"></script>
<script src="../assets/js/game-line/data/village.js"></script>
<script src="../assets/js/game-line/data/old-house.js"></script>
<script src="../assets/js/game-line/game/story-validator.js"></script>
<script src="../assets/js/game-line/game/story-runtime.js"></script>
<script src="../assets/js/game-line/game/story-request.js"></script>
<script src="../assets/js/game-line/game/story-engine.js"></script>
```

加载成功后唯一公开入口为：

```js
window.WhiteLamp.story.enterStory(request)
```

启动时控制台会打印模块版本、接口版本、起止 Node、Node 数量和预检结果。预检失败时入口只返回 `STORY_INVALID_NODE_DATA`，不会跳过坏数据继续游戏。

## 3. 全局协调器的固定流程

1. 外部模块把事件交给全局状态模块；状态模块校验来源、`eventId` 和 `causedByCommandId` 后提交事实。
2. 协调器用提交后的事实和当前剧情检查点调用 `enterStory()`。
3. 协调器把响应中的 `commit.checkpoint` 与 `commit.events` 作为一次事务提交。
4. 提交失败时保持旧检查点，不分发成功通知、命令或新展示。
5. 提交成功后分发 `notifications`、`commands` 和 `presentation`。

剧情内核无状态，不使用 DOM 或 `localStorage`。协调器负责持久化去重 `requestId` 和外部 `eventId`；状态模块负责按 `onceKey` 防止重复发奖。

新游戏的剧情事实必须为空、检查点必须为 `null`。初始背包由全局初始状态工厂放入 `burned-work-id` 和 `blue-glass-bead`，不能让剧情内核私自补写。

状态模块提交以下事件后，还要产生对应事实：

| 状态事件 | 派生事实 |
| --- | --- |
| `ITEM_ACQUIRED key-a` | `key-a-acquired` |
| `ITEM_ACQUIRED map-fragment-1/2/3` | 对应的 `map-fragment-1/2/3-acquired` |
| `ITEM_ACQUIRED restored-village-map` | `restored-village-map-acquired` |
| `LOCATION_UNLOCKED old-house` | `old-house-unlocked` |

状态模块不得根据外部事件自行选择下一 Node，也不得直接修改剧情检查点内部字段。

## 4. 文案修改规则

叙述和系统提示位于三个阶段数据文件的 `presentations[].blocks`。修改措辞、增加或删减文本块、调整分页或改变对话轮数，不需要修改 Node ID 或 `revision`。

实现层在最低 Node 格式上增加两个内部字段：

| 字段 | 固定内容 |
| --- | --- |
| `presentations[]` | `id`、`when`、`sceneId`、`blocks`、`actionIds` |
| `blocks[]` | `id`、`blockType`、`text`；类型只允许 `narration` 或 `system` |
| `actions[]` | `id`、`label`、`actionType`、`availableWhen`、`effect` |

同一状态最多命中一个 presentation；同时命中多个时会返回 `STORY_INVALID_NODE_DATA`，不会按数组顺序猜测。`presentation` 和 `block` 的 ID 用于渲染去重，不进入剧情检查点。

人物对白由对话模块根据剧情命令中的 `goals` 编排；剧情模块不检查句数。只有修改里程碑、完成条件、事实含义或转移关系时才增加 `revision`，并另行提供明确的旧检查点迁移；当前 V1 没有通用迁移框架。
