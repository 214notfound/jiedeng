\chapter{游戏设计详解}

\section{主线剧情}
\subsection{开场与物品}

玩家从祠堂的地上醒来，身上只有三样东西：一张烧毁大半、只剩姓氏的工作证，一颗蓝玻璃珠，一把没有标记的老钥匙。守在一旁的年轻人自称小周，告诉他你是公司外聘的逻辑分析师，来调查村里的闹鬼事件，前几天摔伤了头。

这句话只有一半是真的，而玩家此刻无从判断是哪一半。\textbf{失忆是整套剧情的启动装置：玩家与主角站在完全相同的信息起点上，村民对同一张脸给出互相矛盾的称呼，有人叫他陈晋年，多数人只认识来谈拆迁的王工程师。}玩家要回答的第一个问题因此不是村里有没有鬼，而是我是谁。

三件开场物品各自是一条身份线的入口。工作证把玩家带向项目档案室，钥匙打开陈家老宅的门，蓝玻璃珠后来在邻镇旧诊所的登记抽屉里找到同款。三条线由身上的物件自然牵引出来，玩家不会觉得自己在完成一份任务清单。

\subsection{三条身份线}

剧情采用一个村庄中枢、三条身份支线、两次强制汇合、一个矿井终局的半线性结构。村口是唯一的中枢，玩家在这里反复出入，把三条线的进度带回同一个地方。

三条线各自回答一个问题。陈晋年线回答我从哪里来，经由旧家、坠沟处、空坟和诊所档案，确认十七年前的兄妹坠沟与父亲的签字。王阙线回答我做过什么，经由村委旧楼、项目部、矿区控制室，确认恐吓系统与封井任务出自谁手。白灯客线回答我删掉了什么，经由拒签户收到的匿名信、废弃邮电所和匿名藏点，确认那份举报在哪些地方被有意留白。

三条线可以交换探索顺序，但交汇点固定。第一次汇合把所有灵异现象的物理成因摊开，第二次汇合还原苏禾之死。玩家在两次汇合之间获得的不只是线索，还有一份越来越难维持的自我解释。

\subsection{五次揭示顺序}

全篇的悬念由五次揭示推进，它们必须按固定顺序发生。任何一次提前泄底，后面几步会一起作废。

\begin{enumerate}
  \item 借灯现象可以人为制造。
  \item 主角就是恐吓系统的设计者王阙。
  \item 王阙正是十七年前失踪的陈晋年。
  \item 白灯客也是主角，而且他的举报刻意避开了自己。
  \item 小周把苏禾推入井中之后，王阙明知她还活着，仍然亲口选择了不报警。
\end{enumerate}

前四次是对玩家认知的推翻，最后一次把矛头转向主角的道德选择。至此玩家已经知道自己操控的这双手做过什么，剩下的问题与推理无关，只与意愿有关。

为了让这个顺序守得住，村民的台词和档案的可辨识度都做了限制：多数人必须认定陈晋年已经死了，只有一位记忆混乱的老人会偶尔喊出这个名字；王阙的正脸资料在档案里始终被剪去；白灯客从不出面，只以变声录音、匿名信和统一的灯形印记存在。

\subsection{五结局设计}

终局不给玩家一句立场选项，而是让玩家实际处置手中的证据材料。交出证据、追逐失败、销毁全部、选择性公开、完整公开，五条路径通向五个稳定结局。

销毁全部，村庄在官方记录里继续什么也没发生。选择性公开，玩家保留矿难与集团违法的部分，删掉王阙设计恐吓、拒绝报警和白灯客删证的记录，以揭密者的身份获利，完成又一次责任切割。完整公开，四组材料一起放出去，主角失去所有干净的身份，第一次以同一个名字承担全部选择。

此设计的用意在于，三个结局的差别不体现在态度，而体现在玩家愿意删掉什么。到这一步，玩家做过的事和主角做过的事是同一件事，这也是项目的核心设问

\section{探索场景}

\subsection{场景即界面}

探索部分放弃列表式菜单，改用整张场景图作为交互载体。全篇共十六余个场景，覆盖村庄中枢、三条身份线、三处玩法场景和五个结局画面。

场景按统一规范绘制与接入，画布 1280×720，16:9，满屏不裁切，图片与热点同步缩放；可调查的对象一律做成场景里的热点，不做平铺网格；单个点击目标不小于 44×44 像素，热点中心间距不小于 144 像素，保证在 390 像素宽的窄屏上依然点准；同一台面超过三个热点时，改为一级热点加放大层。

在此规则约束下，玩家在场景里看到的每一样东西，都可点、可问、可拿，场景美术因此不能只是背景板，它同时是线索的容器。

场景中的对象在被调查后会改变状态，或在视觉上留下痕迹，或标记为已调查，玩家不会重复拿到同一条线索，也不会有漏掉某个对象就必须重开一局的焦虑。

\subsection{人物对话}

不同角色说不同的话是核心塑造规则。小周冷静克制，从不用感叹句，也很少直接否定主角，在关心主角的同时显露出一些异常；村民保留口语和方言味，同一件事各有各的说法；主角的内心独白短，且多数以疑问收尾。

信息有分寸。村民群体被拆成有差别的记忆持有者：拒签户、已经搬走的人、当年收过补偿的人、仍然相信借灯禁忌的老人，对十七年前的事故各有各的版本。玩家在村口收集到的说法互相冲突，冲突本身就被设计成线索。

\subsection{背包与线索}

调查得到的物证进入背包，线索独立成页，两者分开管理。玩家拿到的是物证，理解的是线索，证据链由线索之间互相印证构成。

三条身份线各自提供的证据能证明的事情是有限的，设计时刻意保留了这一点。陈晋年线的照片、票据与空坟记录能证明兄妹坠沟和陈晋年生还，证明不了集团的违法；王阙线的背景调查与调试录像能证明恐吓系统出自谁手，证明不了他事前知道旧事故的真相；白灯客线的匿名信与删改记录能证明泄密时回避了自身责任，不能等同于完整自首。任何一条线单独拿出来都推翻不了全部假设，玩家必须把三条线的证据拼在一起。

\section{核心交互}

\subsection{剧情对话}

旁白、系统提示和人物对白统一走阅读组件。组件负责逐段显示、控制继续与关闭；剧情模块决定说什么、能做什么；对话模块负责具体的角色对白。三层分开之后，改一句台词不需要动流程，加一个流程节点也不需要重写文案。

对话框在窄屏下换行重排，发言者名牌与正文分行渲染，多行文本不会顶掉名牌。人物立绘按情绪切换，配合字号与留白的变化，让长时间阅读不至于疲劳。

V2 之后游戏不设影响主线的分支选项。玩家只在剧情明确给出操作时才能提交选择，普通的继续阅读不会改变任何状态。这条限制是刻意的：故事要的是玩家沿着一条确定的因果链走到底，而不是在岔路口反复权衡。

\subsection{四种小游戏}

小游戏嵌在剧情节点上，玩完把结果回写给剧情模块，由剧情模块决定后续走向。四个小游戏分别承担不同的叙事功能。

\textbf{手绘地图复原}放在村口，玩家从三名村民处取得地图碎片后拼成完整村庄图，拼好即解锁通往陈家老宅的路径。它教玩家读懂这个村庄的空间关系。

\textbf{拆鬼}安排在第一次汇合。玩家要逆向追踪童谣、白灯和湿脚印的来源，关闭其中一组装置。每种装置都有供电范围、触发条件和可以被反向利用的缺陷，玩家利用延迟或供电盲区躲过下一次触发。恐怖规则在这里正式成为玩法规则，也是全篇唯一一处让玩家主动拆解恐惧的地方。

\textbf{路线解谜}发生在旧矿井。玩家依照原始矿图从排水洞绕开封堵，检查两道挡墙、废石填层和速凝浆的痕迹。这一段的目的是让玩家亲手确认一件事：当晚封掉的只是唯一公开入口，竖井从来没有被灌满，井下的人本可以被救出来。

\textbf{终局追逐}放在数据机房，详见本章第四节。

四个小游戏都不以难度取胜。它们是让玩家在关键节点上动手，而不是让玩家卡关。

\subsection{恐怖表现与设计}

恐怖表现集中在三类手法上，都服务于同一件事——让玩家相信有什么东西在这个村子里。

音效是其中最重要的一层。檐下的雨声和环境底噪持续存在，广播里的童谣带着电流杂音定时出现，远处传来爆破的回声。这些声音同时属于村庄的日常和恐吓装置的一部分，玩家在中段之前无法分辨，中段之后回头看，会发现每一处声音都解释得通。

画面层面用黑屏、花屏和抖动处理关键转场，全篇共十一余处。它们的共同规则是只出现在状态切换的瞬间，用来制造一次短暂的失控感，不侵入阅读区域，不影响正在显示的文本。祠堂断电那一段是其中最典型的一处，灯灭与转场叠在一起。

过场视频用在几个无法用静态场景交代的位置，配合白灯 CG 与画面闪黑衔接前后场景。人物的情绪转折、时间的跳跃、回忆片段的插入都交给视频处理，避免用大段旁白去解释画面。

所有恐怖手法的边界是明确的：不打断操作，不遮挡文本，不靠突然的巨响吓人。真正的压力来自玩家逐渐意识到自己拆解的每一个装置都眼熟。

\subsection{存档与进度恢复}

游戏状态保存在浏览器本地，包含剧情检查点、已确认事实、调查进度、对话进度、物品、线索、地点、地图拼图结果、选择和成就。

剧情检查点是唯一可信的进度来源。页面、探索、对话和小游戏都不能自行修改当前节点，一次操作只有在状态提交和存档成功之后，才会在界面上显示为完成。这样做的收益在协作阶段体现得最明显：五个人分头开发，谁改动一个模块都不会让另一处的进度对不上。

注册用户和游客使用各自独立的本地存储空间，互不覆盖。系统分别处理没有存档、存档损坏、版本不兼容和浏览器无法写入四种情况。恢复失败时保留原始数据并如实告知玩家，不会悄悄当成一局新游戏重新开始。

\section{附加功能}

\subsection{终局追逐与生命值系统}
设计的终局小游戏是数据机房主题追逐关卡，玩家需躲避小周追捕，收集三份关键证据并撤离出口。关卡引入生命值系统，强化追逐生存压力；受击后提供 1 秒无敌时间，防止连续碰撞瞬间暴毙，平衡游玩容错。对斜向移动做速度归一化处理，走位操控更加稳定流畅。证据具备防重复计数逻辑，关卡成败结果可回传主线，联动整体剧情。俯视视角角色立绘搭配密闭机房场景，便于观察敌人动向，进一步烘托出悬疑紧迫的逃亡氛围。

\subsection{成就系统}

成就页共收录 14 条成就，按剧情推进的层次分成三组：调查札记 3 条，灯下真相 6 条，终局余烬 5 条。页面标题是雨夜留痕，顶部给出解锁进度与一条进度条，下面是三组成就卡片。

每条成就的解锁条件不是另写一套判定，而是直接声明它依赖哪些已经登记的剧情事实。地图复原完成对应残图归一，确认异象系人为制造对应灯下无人，三重身份合并对应三名照一身，终局追逐生还对应雨幕留痕。成就因此不需要维护第二份进度，剧情走到哪里，成就就跟到哪里。

五条结局成就被标记为隐藏条目。未解锁时，成就页只显示未明之章配合罗马数字序号，描述文案完全不渲染。这条规则是为了防住一个很容易踩的坑：成就页是最容易被玩家提前翻看的地方，如果把五个结局的名字直接列出来，整条主线的走向就白送了。成就页因此对未解锁的结局保持沉默。

卡片左侧用一个字区分状态，已解锁显示灯，未解锁显示影。规则模块判定出某条成就可以解锁，不等于它已经解锁——事件要由状态模块按游戏局、存储范围和幂等键提交成功，卡片才会点亮。同一份成就模块只允许一个视图负责新解锁提示，避免同一件事被提示两次。

数据异常被限制在单条记录内。某条成就缺少对应剧情事实，或解锁时间格式无效，只有该条显示记录异常，其余卡片和整个页面的生命周期不受影响。读档失败也按原因分别处理：存档损坏、版本不兼容、登录身份与存档不匹配、浏览器存储不可用各有各的提示；没有存档不算失败，页面会显示当前还没有游戏存档

\subsection{项目组信息}

制作组与项目介绍分成两个页面，五名成员另各有独立页面，页面之间互相链接。制作组页面的内容分三块：团队概览给出组名白灯客、项目名与版本号，以及一句团队自述；成员档案列出五人的头像、角色与一句话简介；项目分工按版本记录每个人做过什么。

这些资料全部集中在一个数据文件里，HTML 只管渲染，不在页面里硬编码成员信息。这条约定的好处在改稿时最明显：调整某位成员的分工或换一张头像，只需要改数据文件的一个字段，五个页面同时生效，不会出现某个页面还是旧版本的尴尬。

成员页面同样按数据驱动的方式渲染。每页有档案编号、姓名缩写标记、头像、角色、一句话简介、个人自述与个人引语。字段为空时不显示，而不是显示待补充的占位文案——这条原则写在了数据文件的文件头，成员没有提供的资料，页面就空着，不替他编。头像加载失败时该图片元素直接移除，不会在页面上留下一个破图。

\subsection{音效与美术}

音效与美术围绕同一套听觉与视觉规范展开。场景美术的配色限定在冷夜、连阴雨、雾和白灯暖光四个方向上，白灯是全篇唯一使用冷青高光的物体，其他光源一律压低。这套限制让玩家在昏暗的场景里始终能一眼找到该点的东西，也让白灯在视觉上始终是例外。

音效负责环境层，美术负责信息层，两者共同的底线是不干扰阅读。具体的视听规范、色彩体系与界面设计见第三章。

\textbf{这一章写的都是我们最终要做成的东西。}四个版本迭代下来，我们把故事结构、场景规则、交互层级和视听手法全部拆开重排过不下五次，为的是让玩家在三个小时之后，回头能找到每一个细节的出处。我们未必把每一项都做到了最好，但每一项为什么这么做，每个人都很清楚。
