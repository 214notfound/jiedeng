\chapter{项目概述}

\section{游戏简介}

\subsection{概述}

《\ProjectName》是一款用原生 HTML5、CSS3 与 JavaScript 写成的浏览器端交互式悬疑叙事游戏。项目不依赖任何前端框架，也没有构建步骤，源码即产物。开发过程按企业级轻量化项目的规范组织：需求先落成文档、拆成 subPR 再动手，代码走功能分支与 PR 评审，五名成员在四个版本中轮换承担项目经理、产品经理、技术负责人等职责。

故事发生在虚构的皖赣交界废弃矿山古村石涧村。村里流传着一条禁忌：死在外地的人若找不到归途，会在雨夜来借一盏没有火焰的白灯笼；灯不能碰，门不能开，更不能回应门外叫自己名字的声音，否则死人会借走你的脸。\textbf{玩家扮演一个在暴雨后从祠堂醒来的失忆者，身上只有一张烧毁大半、仅剩姓氏可辨的工作证和一颗蓝玻璃珠。他要在查清村庄闹鬼真相的同时，回答一个更麻烦的问题：我是谁。}

项目想在三个方向上都有所交代：工程上有一套可追溯的规范流程，叙事上有一个经得起反复推敲的反转结构，主题上留下一点值得回味的感受。

\subsection{核心玩法循环}

游戏的基本循环是一条闭环，玩家的每一步操作最终都落在同一份进度记录上：

\begin{center}
\small
\textbf{阅读剧情 $\rightarrow$ 探索场景 $\rightarrow$ 调查与对话 $\rightarrow$ 收集线索 $\rightarrow$ 完成小游戏 $\rightarrow$ 作出抉择}
\end{center}

走完这一轮，剧情推进到下一个节点，循环重新开始。

阅读环节按段落推进剧情，对话带发言者名牌，独白与旁白分开渲染。探索环节里，场景中的发光热点是唯一的交互入口，点击物品或人物会触发调查、对话或线索详情，得到的物证进入背包。小游戏嵌在剧情节点上，地图复原、拆鬼、矿井通路和终局追逐都在此列，结果会回写到剧情状态。

\subsection{创作背景与理念}

故事来自小组的原创悬疑剧本，表层框架借用了南方山村雨夜借灯的民俗传说，氛围落在废弃矿山古村的落寞上，重心则始终放在人物的命运纠葛和选择上。

石涧村的这条禁忌是完整的：死者在外地找不到归途，会在雨夜借一盏没有火焰的白灯；活人若开门回应，脸就会被借走。它既是恐怖氛围的来源，也是叙事的机关。白灯笼、广播里的童谣、只有进没有出的湿脚印、墙上写着的已故村民名字，这些在前半段看起来无法解释的现象，故事进行到中段会告诉玩家它们全都有物理成因。真正推动悲剧的，是集团、村民、父亲和主角各自作出的选择。白灯象征的不是超自然力量，而是人借传说掩盖责任。

主人公的一生是一条闭合的因果链，每个阶段的决定都在为最后的结局埋线。

童年时矿难夺走了他的亲人，家庭随之破碎。他选择逃离故乡，毁容改名，把过去整个切开，以为这样就能重新活一次。创伤并没有因此愈合，只是被压到了意识深处。

成年后他被迫回到故地，故乡的一草一木把深埋的恐惧全部唤了回来。他没有选择直面，而是照着童年的记忆复刻出一套恐吓装置，把自己最怕的东西变成了威胁别人的工具。

为了掩盖罪行，他又分裂出白灯客这个匿名身份，抹掉作恶的证据，试图在道德上把自己和做过的事切开。这个身份既是自保的手段，也是人格崩塌的标志。

全程的沉默并没有换来救赎。他越是逃避，越是被迫面对；越是沉默，罪责越重。自我救赎的失败，构成了整条命运逻辑的闭环。

\section{体验定位}

\subsection{玩家画像}

《\ProjectName》面向的是愿意花两三个小时读完一个完整故事的人。这一版预计游玩时长三小时左右，节奏由文本和调查推动，不设操作门槛：V2 之后核心操作只剩鼠标点击，键盘只用于少量快捷键。

游戏不要求玩家事先了解任何背景知识，也不依赖前作。三小时的流程里，前三分之一用来建立悬念，中间用来推翻玩家已经建立的判断，最后一段留给一个没有标准答案的决定。


\subsection{沉浸式体验}

沉浸感的建立方式，主要是在几个地方不给玩家退路。

开场失忆让玩家和主角站在完全相同的起点。你不知道自己是谁，村民对你的称呼也互相矛盾：多数人认定陈晋年十七年前就死了，只认识来谈拆迁的王工程师；一个记忆混乱的老人会突然喊出陈晋年的名字。玩家手里的信息、心里的疑问，和屏幕里的主角一模一样。

游戏里没有太多靠突然的画面和音效吓人。恐怖感来自另一件事：中段揭露所有灵异现象都是人为装置之后，玩家会认出这些装置的元素全部来自主角的童年记忆。我们希望做出这样“可怕的不是鬼，而是人”的艺术反转效果，从而引发玩家的思考与喜爱。

场景细节同样在为这件事服务。檐下的雨声、排水渠里流动的水、广播里带着电流杂音的童谣、雨后只有进没有出的湿脚印，每一样都同时属于村庄的日常和恐吓装置的一部分。

界面上则尽量不打断玩家。同一时刻只允许存在一种主状态，线索详情、背包或小游戏窗口打开时，背后的场景会被锁住，关闭后回到原来的状态。

\subsection{感受主旨}

故事表面上问的是村里有没有鬼，中段变成谁在装鬼，后段揭晓装鬼的人就是主角。真正的问题留到了最后：他为什么需要一个鬼。

只要存在一个外在的、说不清的力量在作祟，他就不用面对另一件事，换句话说，这个村子里所有的苦难，都是活人做出来的选择。

终局的处理方式呼应了这一点。玩家不是从几个结局里选一句话，而是决定保留哪几组证据、删掉哪几组。当玩家成功逃离小周之后，销毁全部、选择性公开、完整公开，三条路的分歧在于玩家愿意承担多少。完整公开意味着同时承认十七年前的矿难、集团的罪行、父亲的隐瞒，以及自己设计恐吓、拒绝施救和删改证据的全部事实。

我们希望玩家在通关之后，对沉默和逃避这两个词多一点警觉，这是这个项目最想留下的一点东西。

\section{项目目标分期与实现边界}

\subsection{分期实现}

项目分四个版本迭代，每一代有明确的交付范围和明确的不做清单。

\textbf{V1} 解决的是有没有的问题，从零到一。站点能跑，剧情能串联，核心是验证可行性。这一代以故事大纲中的 14 个探索阶段作为全局口径，V1 只完成前三个：祠堂醒来、村口开放、陈家老宅。同时交付登录、注册、游客三种进入方式，主菜单、成就、项目介绍、制作组以及五名成员各自的独立页面，共计八个以上 HTML 页面。小游戏做了手绘地图复原一个，成就系统做到能解锁第一项，存档先只存在浏览器本地。V1 明确不做的部分，向后的剧情，第二个小游戏、完整证据链、全部身份反转和多结局等等。

\textbf{V2} 不新增任何剧情，只重做游戏内的交互方式。界面被拆成五种互斥状态：看剧情、逛场景、看线索详情、看背包、玩小游戏。同一时刻只能处于其中一种，弹窗打开时背后的场景锁死。探索从列表式操作改成直接点击场景里的发光热点。这一版还统一了进度来源，storyCheckpoint 成为唯一的剧情进度记录，其他字段只作为由它生成的只读投影存在，避免全局、剧情和探索各记一份互相打架的进度。

\textbf{V3} 把故事推到结局。老宅不再是整局的终点，而是后半段调查的入口。这一代新增 28 个运行时 Node 和四个后续剧情阶段，把三条身份线的外围调查接入正式流程，新做三个小游戏，并把五个结局全部跑通。它的技术前提是 V2 必须先验收并合入 main，V3 分支从包含完整 V2 的最新 main 上重建，不允许在缺失 V2 的旧分支上批量开工。

\textbf{V4} 解决的是好不好的问题，不再增加结构性内容，做的是内容改写与体验收尾。剧情对话按 46 个改写块全面修订，覆盖序幕到终局的全流程；对话框补上响应式；新增 11 处转场效果；插入过场视频；菜单页、成就页和背包页的展示细节陆续调整。这一版还处理了一个具体的渲染问题：探索热点被点击后可能走阅读视图或物品详情弹窗两条不同的路径，两条路径对多行文本和发言者名牌的处理规则并不相同，写文案时必须先判断这段话会走哪条路。

\subsection{实现难点与挑战}

反转节奏是最难控制的一件事。游戏的核心是三重身份的逐步揭露：先让玩家确认所谓闹鬼是人为的，再确认主角就是设计这套装置的王阙，接着确认王阙就是十七年前失踪的陈晋年，最后确认匿名举报的白灯客也是同一个人。四次揭示必须按固定顺序发生，任何一次提前泄底，后面几步就全部作废。大纲评审时反复调整过村民的台词，把原本多人直接叫出主角名字的写法删掉，只留一个记忆混乱的老人偶尔喊出陈晋年的名字，多数村民必须明确认为陈晋年已经死了。

故事逻辑的自洽花了比预想更多的时间。大纲修订清单里列出的问题大多属于这一类：搜救队第二天就找到两个孩子，和陈晋年昏迷两天后才被采药人发现，这两件事不能同时成立；妹妹事故的逐日时间线前后指代不清；陈晋年在早期稿子里被写成冻结在十七岁，但他其实是十七岁的兄长，坠入采坑的是妹妹。父亲的动机也重写过，最初只写他远远看见白布却不敢确认，心理因果太弱，改成了他既受过胁迫、也主动毁过证，这样他后来十七年不寻找可能生还的儿子才站得住。

技术上的主要矛盾是状态一致性。剧情、探索、对话、背包、成就各自都有进度要记，如果每个模块各存一份，迟早会出现同一次操作在不同模块里结果不一致的情况。V2 的解决办法是收敛到单一进度源，并规定新代码不得读写兼容字段来决定剧情推进。协作层面同样靠约定约束：接口先给真实输入输出，双方共同跑通才算接入；页面结构、剧情文本、热点规则、场景美术、状态与存档分别归属到人，问题按归属回退；开发者不能做自己 PR 的唯一审查人。

还有一类困难来自恐怖规则要同时是玩法规则这条要求。白灯、广播、湿脚印和墙上姓名都成立，但每种装置都必须有供电范围、触发条件和可以被玩家反向利用的缺陷，否则操作者就显得无所不能，恐怖也就失去了张力。拆鬼那一段的设计正是围绕这条原则展开的：玩家要逆向追踪三种异象的来源，利用延迟或供电盲区躲过下一次触发。

\textbf{团队的每一位成员都在这个项目中投入了超出课业要求的心力。我们反复推敲每一句对白的分寸、每一个反转的节奏、每一条命运线索的闭环，因为我们确实相信这个故事值得被好好讲出来。我们未必做到了完美，但我们做到了诚实。如果玩家在走出这个故事之后，能对沉默和逃避多一分警觉，对面对多一分勇气，那便是我们最大的回馈。}
