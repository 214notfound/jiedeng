## 二、写文案前必读

### 标记 vs 名牌

| 写法 | 含义 | 玩家看到 |
|---|---|---|
| `【小周】` `【老板】` `【你】` | 真名牌 | 带名字的框 + 正文 |
| `【独白】` | 真名牌 | 写着「独白」的框 + 正文 |
| `【旁白】` | 叙述标记 | 只有正文，**不出名牌** |
| `[旁白]` `[系统]` `[独白]` | 文档标记 | 不写进代码，只用来决定 `blockType` |

`【旁白】` 的静默规则在 [game-ui.js](../../../assets/js/core/game-ui.js) 的 `SILENT_SPEAKER_LABELS`。要再加静默标记，往这个集合里加即可。

### 两条渲染路径（决定多行怎么写）

探索热点被点击后走哪条路，取决于该 action 的 id 在 `items.js` 里有没有同名物品：

| 路径 | 触发条件 | `\n` | `【X】` |
|---|---|---|---|
| **阅读视图** | action id 不在 `items.js` 中；或 game-line 的 `presentations[].blocks[]`；或对话 `text` | 分页，每行一条 | 行首标签出名牌 ✅ |
| **物品详情弹窗** | action id 在 `items.js` 中（走 `inventoryView.openTarget`） | 折叠成一个空格 | 连方括号字面显示 ❌ |

**结论**：写在弹窗路径上的文案，多行必须手工合并成一段，也不能用名牌。

名牌识别要求标签前是**行首或空白字符**。中文标点或汉字后面跟的 `【X】` 不会被识别，会原样显示。

## 五、遗留问题

**数据层面**

- `conversations.js` 里 `shopkeeper-inquiry` 和 `identity-conflict` 的 `text` 属于被 V2 覆盖的**死文本**，仍是旧文案。两处描述同一场戏，将来改动容易改错地方——建议统一到 V2 一侧。
- O-3 的活文本写在 `conversations-v2.js`，O-4 / F-2 写在 `conversations.js`，同一批改动落在两个文件里，风格不统一。

**渲染层面**

- 行内的 `【旁白】`（前面是汉字或中文标点）不会被识别为标签，会字面显示。当前 22 处 `【旁白】` 全在行首，暂不受影响。

| 位置 | 问题 |

| 行 179 | 称 `\n` 不分页——与 `splitReadingText` 实际行为相反 |
